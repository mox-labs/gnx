# AGENTS.md

For an agent reading or working in this repository. People start at [README.md](README.md).

## What gnx is

Python tools and libraries that make agents more effective and their work inspectable, plus
skills shipped as Claude Code plugins. Owned by yzavyas, built mostly by Claude:
[how](docs/content/start/2-how-gnx-is-built.md).

## Which tool for which ask

| The person wants to | Tool | Its guide, for the installed version |
|---|---|---|
| decide a question about an agent or a service by experiment (evals, A/B, regressions, load, mutation testing) | `ix` | `ix --skill`, then `ix --skill -r <name>` |
| collect from APIs, CLIs, web pages, documents or MCP servers, and query it with SQL | `recon` | `recon --skill` |
| compose components and agents, with every row recorded | `matrix` | `matrix --skill` |
| make one model call to any model family | `hardline` | `hardline --skill` |
| audit a project's agent organization (`.claude/`, `CLAUDE.md`) | `dao` | `dao check <project>`; `dao --help` lists the rest |
| change which components ship as plugins | `gnx` | `gnx --help` |

Read the `--skill` text before writing a config: it matches the installed version, where a
README may be ahead of it. `matrix-hardline` and `ix-cosmic-ray` are libraries with no command;
their READMEs say when they are needed.

## Running the tools from a clone

```
uv --project components/capabilities run <tool> ...
```

Never `pip install matrix` or `ix`: those names on PyPI are other projects. Released installs
pin a tag; the [README](README.md#install-a-release) has the lines.

## Which file answers what

| Question | File |
|---|---|
| What a package does, how to install it, a first run | `components/capabilities/<pkg>/README.md` |
| What each surface promises, and how stable it is | `components/capabilities/<pkg>/CONTRACT.md` (where present) |
| Its trust boundaries | `components/capabilities/<pkg>/SECURITY.md` |
| What changed, per release | `components/capabilities/<pkg>/CHANGELOG.md` |
| Why it is built the way it is | `components/capabilities/<pkg>/docs/design/` (hardline, matrix, ix, recon) |
| Which components ship in which plugin | `components/bundles.yaml` |
| The gates | `justfile` |
| How to contribute | [CONTRIBUTING.md](CONTRIBUTING.md) |

## Working in the repository

- `just check` before a commit (the pre-commit hook runs it); `just ci` is the full gate.
- `plugins/` and `.claude-plugin/marketplace.json` are generated by `gnx build`. Never edit them
  by hand; `just projection` fails on drift.
- yzavyas rules on decisions and merges to `main`. A design decision the owner has not ruled
  on is recorded as yours, in the package's design record: the alternatives weighed, the
  verdict and its named weakness.
- Commits follow Conventional Commits; see CONTRIBUTING.md.
