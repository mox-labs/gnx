# The collaboration method

> This doc set was not dictated and was not autogenerated. It was built by a human and an agent
> working under a discipline — one that the catalog is meant to distribute (the cix family).
> The method is worth stating because the doc set is evidence for it: if the discipline works,
> the artifact reads like it.

---

## The fidelity ladder sets the bar per thing

Dirt road → cobble → tarmac. A happy path, then edges and tests, then hardened. The trap is doing one to everything: tarmac the throwaway and you waste; dirt-road the load-bearing and you take on debt. So the bar is set *per thing*, before building it — and the milestones are fidelity gates. The Start pages are tarmac (they're the front door). The component catalog tiers its entries the same way, and refuses to tarmac a vapor component into a page it can't honestly fill.

---

## The agent generates; the human comprehends

The division of labor is deliberate. The agent drafts at throughput; the human reviews, refines, and authorizes. The comprehension is the point — an artifact the human cannot reconstruct is not done, however polished. The [feedback loop](/docs/the-feedback-loop) is where this happens: the human's comment is comprehension exposed, the revision is the response, and convergence is the close. The agent is a thinking partner inside the frame, not a substitute for the human's judgment outside it.

---

## Falsification before advocacy

A recommendation carries its strongest counter-argument, or it isn't ready. The design docs end in open questions for the same reason: the honest move is to name what would make the claim wrong, not to defend the claim. The ship-gate enforces the same posture from the outside — an out-of-family evaluator exists precisely so the maker can't advocate its way past a weak spot.

---

## Memory and the handoff kit carry context across sessions

Two mechanisms keep the work coherent across the gaps between sessions. A persistent, file-backed **memory** holds what was non-obvious and durable — the settled framings, the scars, the verified mechanics — so a fresh session doesn't re-derive them. And a **handoff kit** (`docs/_handoff/`) holds the executable brief: the plan, the rubric extension, the design decisions. Doc-driven design ties it together — the doc set's maturity *is* the spec's maturity, so the site is both the deliverable and the place the next session gets the point.

---

## The method is the product, recursively

gnx's founding move will be `gnx init gnx` — the catalog initialized by its own CLI, running its own core set. This doc set is the same move at the documentation layer: built with the cix family (the discipline, the review panel, the rhetoric components) that the catalog is meant to distribute. The bet is that a method good enough to build the thing is a method worth packaging — and the evidence is whether what you're reading holds up.
