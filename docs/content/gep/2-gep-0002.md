# GEP-0002: the provides value-space

**Accepted — the shape rule is ratified: an entry that parses as a `type_url` is a port; a dotted-lowercase phrase is a discovery tag; Skills legitimately carry tags alone. The typed-ports reading composes with it — `requires`/`provides` are `type_url`s, composition matches provided→required by string equality, so ports do topology and tags do discovery, one field carrying both populations discriminated by parse. Deferrable details stay deferred.**

## Summary

One shape rule ends the double-typing: a `provides` entry that **parses as a `type_url`** (under GEP-0001's identity grammar) is a **port**; a dotted-lowercase phrase that does not is a **non-normative discovery tag**. Ports are join keys — they participate in topology derivation and capability closure. Tags are search hints — they feed discovery and plugin keywords, and nothing ever joins on them. A controlled tag vocabulary is explicitly deferred, and can be, precisely because tags are not join keys.

## Motivation

`provides` currently plays three simultaneous roles with nothing distinguishing them:

1. **Ports** — slick's docstring: port declarations for composition, the thing `requires` matches against, the input to capability-closure computation.
2. **Discovery tags** — every real component: `intent.hardening`, `intent.triguna-halt`, `inquiry.fallacy-gate` — dotted phrases with no schema behind them.
3. **Plugin keywords** — the projector maps `provides` straight into `plugin.json` keywords.

Left mixed, the composer's port-matching premise silently degrades to string matching over a blended vocabulary — `session-memory` vs `memory` is the search-side pollution, and a discovery search would run over exactly this index. GEP-0000's sequencing names G2 (with G1) as what gates the next component's registration — and intake is mass registration.

This GEP also records a correction a manifest deep-dive forced: the earlier claim that a doctrine-authored manifest *"fails to parse"* is the wrong shape. It **parses** (serde defaults; the crate has no `deny_unknown_fields`) and **silently loses its topology fields**. Silent loss, not parse failure — arguably worse, and a different thing to defend against: a linter, not a parser fix.

## Guide-level explanation

An author lists what the component genuinely emits as typed output, and what it should be findable by:

```yaml
provides:
  - gnx.dev.v1.recon-report   # parses as a type_url → a PORT
  - recon.search              # dotted lowercase, no version segment → a TAG
```

Nothing else changes. Skills — provides-only axioms — usually carry tags alone, and that is honest: for the skill-bundle class, ports do no work, and the shape rule makes that legible instead of embarrassing.

## Reference-level explanation

1. **The rule.** An entry is a **port** iff it parses under GEP-0001's grammar (namespace segments + `v[0-9]+` + Resource). Otherwise it is a **tag**. No third case; near-misses are linter warnings (an entry that is *almost* a `type_url` is more likely a typo'd port than an exotic tag).
2. **Ports** participate in: topology derivation (the Flow compile, GEP-0003), `requires` matching, and capability closure — computable from `requires`/`provides` alone on the shipped five fields.
3. **Tags** feed: catalog search, catalog rendering, and the projector's keyword mapping. Tags are **re-lexiconable post-hoc** — renaming a tag breaks nothing structural, which is exactly why the controlled vocabulary can wait.
4. **Trust boundary note.** Tag quality — and manifest prose quality generally — can never be the trust signal. The pooling-equilibrium finding: cheap legibility makes fake-composable surfaces indistinguishable from real ones, so if tags carried trust, polishing tags would mint trust. Provenance and accreditation carry trust (GEP-0008, the wall); tags carry findability. The rule keeps those separable by construction.
5. **Scope.** This GEP rules the **value-space inside the shipped fields**. It does not rule field *names* — whether the overlay ever grows explicit `consumes`/`produces` topology fields is GEP-0009's deferral (waiting on a component the shape rule cannot serve).

## Drawbacks

The rule is a parse-based heuristic — a malformed port silently demotes to a tag. The linter's near-miss warning is the mitigation, and the failure is at least *visible* (a port that never matches fails the Flow compile loudly). And one field carrying two populations remains a squint; we accept the squint over growing the overlay for a distinction the parse already makes.

## Rationale and alternatives

- **Split fields** (`provides` vs `tags`) — cleaner, rejected for now: it grows the on-disk contract for zero additional information, and the migration is trivially mechanical later if the squint costs real bugs.
- **Schema-per-tag** — absurd on its face: every semantic tag would need an `api/` entry, which converts a search hint into a governance object.
- **Controlled vocabulary now** — deferred: curation cost before scale exists, and tags being non-join makes drift survivable. Trigger to revisit: observed search-side pollution (the `session-memory`/`memory` class) in a populated catalog.

## Prior art

npm keywords (free tags, no join semantics — and the discovery pollution that followed at scale: the cautionary tale for the deferred lexicon); Kubernetes labels vs selectors (free-form labels, joining selectors — the same split, load-bearing for a decade); Cargo features (typed and closed — what our ports are, not what our tags are).

## Unresolved questions

- When (if ever) the tag lexicon becomes curated — trigger named above.
- Single-`produces` arity as an intake convention — ruled alongside the overlay contract (GEP-0009).
- Whether ports eventually get their own fields — deferred to the first component that needs a distinction the shape rule cannot carry.
