# GEP-0001: the identity grammar

**Accepted — the casing pick is ruled: kebab-case resources. Every example here is kebab-case. slick co-owns the grammar (per GEP-0000); the co-ratification is a propagation task, not an open question. This is a near-one-way door: a serialized `type_url` is permanent.**

## Summary

The catalog mints every component's `type_url` under a gnx-owned namespace, in the shipped version-medial dotted form `<namespace>.<ver>.<resource>`, under one casing rule (kebab-case), with **kind never encoded in a segment**, and with a namespace-extraction rule that makes portability computable instead of improvised. Adopted components get gnx-minted names — provenance lives in `source` and `relations`, never in the identity.

## Motivation

`type_url` is the single join key of the entire system. It is the one string that bridges the authoring face and the runtime face — slick's manifest states it directly: *the `Manifest.type_url` is the `TypedStruct.type_url`* — and every downstream contract keys on it by **string equality**: the typed registry's factory lookup, a runtime's produce-check, the ports in `requires`/`provides`, the edges in `relations`, and the frame vocabulary any future protocol carries. There is no second chance at this string: both external adjudication and shipped practice treat serialized `type_url`s as permanent.

And it is currently governed by example only, with the examples in open disagreement:

- The grammar reference *once* documented `<namespace>.<version>.<resource>` with PascalCase resource names, while **every real component on disk is kebab-case** (`gnx.dev.v1.intent-hardening`) — the catalog contradicted its own convention. The docs are now reconciled to kebab-case; the ancestor-namespace doctests in the shipped crate remain the last residue.
- slick's shipped crate examples predate this ruling and carry an ancestor namespace in mixed form — the canonical examples disagree with the canonical prose. A correction pass owes the docs and doctests the ruled form.
- The reference runtime lineage documents a slash-form variant (`<ns>.v<version>/<resource>`) in a docstring — unenforced, never validated, with no code path bringing the two grammars together. A fork that costs zero code changes to settle, and a runtime error if left to collide later.
- `apiVersion` uses slashes (`slick.dev/v1`) while `type_url` uses dots; the derivation rule between them is explicitly open, and the catalog page had to improvise a namespace-extraction rule because none exists.

Population is mass registration. Every manifest authored before this ruling encodes a guess into a permanent string.

## Guide-level explanation

When a component registers, **the catalog mints its identity**. An author does not choose a namespace; the catalog assigns one from the registration context:

```yaml
type_url: gnx.dev.v1.intent-hardening   # kebab-case resource
```

Adopted components are minted under the gnx namespace, not inherited: a component brought in from an ancestor tooling family drops its old namespace, its `type_url` is re-minted as `gnx.dev.v1.<name>`, and the lineage is recorded where provenance belongs — `source` points at the adopted tree, `relations` carries the alias. This **dissolves** any question about which side of an ancestor's unfinished rename to inherit: we inherit neither.

## Reference-level explanation

1. **Form.** `type_url = <namespace> "." <ver> "." <resource>` — dots only. `<namespace>` is one or more dotted lowercase segments (`gnx.dev`); `<ver>` matches `v[0-9]+` and is **version-medial**, matching slick's shipped format; `<resource>` is the final segment, the component name, in **kebab-case**.
2. **Minting authority.** The catalog is the sole minting surface for `gnx.dev.*`. Schemas live under `api/`; one namespace authority produces global uniqueness the same way the protobuf package tree does. No component self-mints.
3. **No kind-derived segments.** `kind` never appears in a `type_url` segment. This clause is load-bearing: the kind count is genuinely open, and this is what keeps that a **two-way door**. A kind reclassification must never be an identity-breaking rename.
4. **Namespace extraction.** The version segment is the first segment matching `v[0-9]+`; everything before it is the namespace, everything after is the resource. Portability computation reads the namespace — `gnx.dev.*` is core; vendor namespaces (per GEP-0006's direction) are Target-scoped. This retires the catalog page's improvisation.
5. **The slash-form is rejected.** The runtime lineage's slash-form is an unenforced docstring; shipped slick, every real manifest, and the protobuf lineage use dots. Settling on dots requires zero code changes in either layer. The docstring gets corrected at that runtime's next doc pass — it currently teaches a dead contract.
6. **A version-terminal variant is flagged, not adopted.** A form placing the version last (`<domain>.<name>.v<n>`) circulated in an untracked design consolidation but never grounded on shipped code. Reconcile it in doctrine; do not mint against it.

## Drawbacks

Re-minting adopted components breaks external references to their old names — mitigated by the alias ledger in `relations`, and honest: those references point at **archived** predecessors whose own registries already disagree with their contents. And one more grammar for authors to learn — mitigated by the linter carrying it, since the crate validates nothing.

## Rationale and alternatives

- **Inherit an ancestor namespace** — rejected: inherits a foreign namespace authority and version metadata proven to drift even under curation. Succession is adoption, not impersonation.
- **Free-form strings** — rejected: portability computation becomes impossible, and the join key degrades exactly the way `provides` tags do without GEP-0002's shape rule.
- **Slash-form** — rejected above; origin precedence (the runtime docstring predates the crate) confers no ruling, and the docstring is the only artifact on its side.

## Prior art

Protobuf `Any` (`type.googleapis.com/<package>.<Message>` — one package tree, global uniqueness); Envoy xDS (an unknown `type_url` NACKs the whole config at load, never at runtime — the model for a linter's admission role); Cargo (append-only name registry; a dead name keeps its slot — the discipline GEP-0000 applies to GEPs themselves).
