# What's real vs planned

**shipped** runs today. **planned** is designed; build starting. **proposed** is a settled or near-settled design decision with no build behind it yet. No page on this site describes a planned capability as if it shipped.

---

## Shipped — runs today

| What | Detail |
|------|--------|
| **slick** grammar (v0.2.0) | The five-field `Manifest` type — `type_url`, `source`, `requires`, `provides`, `relations`. Ships as the `slickit` Rust crate, behind the `manifest` feature. In-memory JSON; Apache-2.0. |
| **Three plugins** | `intent-hardening`, `rational-inquiry`, `recon` — projected as Claude Code plugins and installable today. The catalog was cut from eleven on 2026-08-19; see below. |
| **The directory marketplace** | The catalog's `.claude-plugin/marketplace.json` at the repo root; the one runnable install path. |
| **The projection pipeline** | `gnx build` generates `plugins/` + the marketplace entry from `components/bundles.yaml`. `gnx build --check` is a commit gate, so the committed projection cannot drift from `components/`. |
| **Four capabilities** | `matrix` (agent runtimes + component DAGs), `ix` (experiments), `recon` (collection), `dao` (organization audit). All `mypy --strict` clean, 407 tests, one `SECURITY.md` each. |
| **The lab** | `lab/` — two experiments runnable with `just evals`. `catalog-routing` measures skill activation against decoys; `sensor-integrity` measures the grading path itself. |

The slick crate ships the manifest *type*; it does not yet enforce much beyond structure. A real validator (`gnx validate` / `slick validate`) is designed. A Python binding for `slickit` is in progress — not yet shipped.

### The components on disk

7 components: **2** Skills, **5** Capabilities, **0** Agents, **0** Flows. Browse them at
[the catalog](/catalog), which reads the directories live.

**69 components moved to `incubator/` on 2026-08-19** — 33 skills and 36 agents, intact and
versioned, out of the catalog and not projected. A live routing eval found a skill failing
to fire on trigger phrases from its own description, and 49 of 76 descriptions exceeded the
catalog-scale target. The catalog now holds what has been evaluated; graduating a component
back is a directory move plus a `bundles.yaml` entry.

Capabilities are Python packages rather than plugins — they install with `uv`/`pip`, from
this repository, since `matrix`, `ix`, `recon` and `dao` are all taken on PyPI by unrelated
projects. The declared-identity layer is deferred until its shape settles in slick.
That is the deliberate state, not a backlog: Manifest v1's shape is being settled in slick,
and minting 76 against a moving spec would mean rewriting 76. The three are the pilot that
tests the grammar. Until the rest follow, a component is **installable but not composable**.

| `rational-inquiry` | Skill | `shipped` | Manifested; projected as a plugin; installs today |

## Planned — designed, build starting

| What | What it will do |
|------|-----------------|
| gnx CLI — `gnx init` | SDK interview → scaffold `claude/ + dao/ + .gnx/` → install a curated set |
| gnx CLI — `gnx component init` | Scaffold a new component (manifest + skill + tests), kind-aware |
| gnx CLI — `gnx add` / `rm` / `update` | Install / remove / update components into a project or user scope |
| gnx CLI — `gnx search` / `inspect` | Agent-facing discovery over the `provides` surface |
| gnx CLI — `gnx validate` | The strict registration gate (manifest, shape rule, ports, kind rules, namespace) |
| gnx **registry** | Validation-at-registration, the `provides` index, accreditation |
| Component **authoring loop** | `component init` → `validate` → `build` → registration |
| Manifests for the full catalog | Blocked on Manifest v1 settling in slick — see above |
| Flow components | The composition layer; `components/flows/` is empty on purpose |
| `api/` **schemas** | Typed config and payload schemas keyed by `type_url`; nothing populates `api/` yet — every config is opaque today |

## Proposed — settled design, no build behind it

| What | Where it is decided |
|------|---------------------|
| **Composition over ports** | ix's DAG nodes carry `requires`/`provides` and run through matrix's `Orchestrator` — real today inside ix. What is *proposed* is the same wiring across catalog components, which needs the manifests. |
| **Identity grammar** | Dotted, version-medial `type_url`, kebab-case resources, catalog-minted namespaces, `kind` never in a segment — ruled; enforcement designed |
| **The shape rule** | A `provides` entry that parses as a `type_url` is a port; a dotted-lowercase phrase is a discovery tag — ratified; enforcement designed |
| **Flow composition** | A `members` list of `(type_url, config)` pairs with derived topology — proposed |
| **The on-disk overlay** | `kind` and `maturity` (on disk today) plus a proposed `version` field, with a projection gate — proposed |

These are open design decisions. The GEP register that tracks them is not published while
the shape is still moving; the decisions above are the summary that is safe to rely on.
