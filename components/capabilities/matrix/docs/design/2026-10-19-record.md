# matrix 0.6.0: design record, 2026-10-19

The judgments made building matrix 0.6.0, recorded by the crafting-aces procedure (its
`SKILL.md`, and `references/ports-and-adapters.md`, `interface.md`, `composition-root.md`).
Rows take the skill's form: claim, test, verdict, named weakness or measure, evidence.
Evidence tags: *observed* (read or run on this tree today), *reported* (a dated document),
*inferred*, *hypothesis*. "The audit" is
`scratch/research-matrix-ix-landscape/2026-10-19/cli-api-audit.md` (reported).

Provenance carried from the skill: the ports-and-adapters layout rests on one author and one
adopting study; the composition root driven by configuration is the ACES framework's
practice, not the canon's; stasis, drag and opacity are that framework's model. Nothing here
is called ACES compliant except as a claim in four parts.

## 8. Decay and failure

| part | bound | what changes after a failure | experiment needed |
|---|---|---|---|
| a transient backend failure | `Retry.attempts`, `max_wait_s`; a wait ends when the run stops | the attempt count is recorded; a component that handed rows over is never retried | measure retry rates against a rate-limited backend |
| reuse (`--from`) of stale rows | a fingerprint of type, config, and an agent step's definition and runtime; reuse needs every provider reused | a changed component and everything downstream run again | none for correctness; a component whose behaviour changes without its config (new code, same config) is reused wrongly: named here, the fingerprint holds no code version |

## 11. After a first drive from the skill

A fresh agent drove matrix 0.6.0 from `matrix --skill` alone and reported seven places it
stalled (*reported*, the coordinator's brief of 2026-10-19). Each change below has a
regression test named after what failed.

| decision | alternatives weighed | verdict and why | named weakness | evidence |
|---|---|---|---|---|
| A config runs on its own with `--only`; `CONFIG` may be named more than once, each above the last | make a named `CONFIG` replace the tiers by default | a flag: the tiers are the documented way your runtimes reach every tool (tier 1), and a project config named on the command line usually wants them; replacing them by default would break that silently. Several `CONFIG`s let a caller pick the tiers it does want (`matrix run ~/.matrix/config.yaml second.yaml --only`) | the flag must be known; the clash it prevents now says so in its fix | *observed*: `test_only_reads_the_named_configs_alone_in_the_order_given`, `test_a_definition_in_two_tiers_is_one_problem_at_the_key_that_read_both` |
| A definition clash is one problem at `matrix.definitions`, and the agents that would use it go unchecked (`complete: false`) | keep the loader's path `name`; keep reporting "no definition named" | the key that brought both files in is the config's; the second problem was a consequence of the first, and said the opposite of what happened | the loader's own message is kept inside, so the text names the other file once | *observed*: same test |
| The spend ceiling is `limits.spend_usd`, held by the executor through a per-run `Spend` the bound agent consults before each session (a context variable, as the span scope is) | count in each component; check only between components | a component that calls several agents, or an agent outside an agent step, is still held; a refused session never starts. "Could pass it" is exact only for a runtime that bounds a session (`budget_usd`, claude-sdk's `max_budget_usd`); for one that does not, the run stops starting sessions at the ceiling and those in flight may pass it, and `plan` says so instead of a number | a session that reports no cost counts its budget or nothing: the `model` runtime (hardline reports tokens, not dollars) is never counted, and `plan` names it as unbounded | *observed*: `tests/test_spend.py`; the installed `claude_agent_sdk` 0.2.139 `ClaudeAgentOptions.max_budget_usd`, read in `types.py` and constructed in `test_the_claude_sdk_runtime_passes_its_budget_to_the_sdk` |
| A refused session is its own error kind, `spend`, exiting `run_failed` like `contract` and `component` | `component` with a reason in `details` | the remedy differs (raise the ceiling, lower a budget), and an agent acts on the kind first; the exit code is the agreed one | a consumer that switches on `details.cause` meets a new value; the set was declared open | *observed*: `test_every_error_kind_has_an_exit_code_and_a_payload` (changed requirement) |
| The task as sent is on the response row (`AgentResponse.task`, stamped by the agent step) and on `matrix.agent.start` | the event alone; stamp it in `BoundAgent` for every caller | the row is the record, read with `jq`; the event covers a step that failed before its row was recorded. Stamping in the step leaves every other caller's responses (ix's) as they were | the `otel` observer does not export the task: prompts stay out of spans unless asked for | *observed*: `test_the_task_as_sent_is_on_the_response_row_and_the_agent_start_event` |
| The mock replies by `responses` (whole task), then `by_agent`, then `default` | key `responses` by agent name | keeping `responses` as it was keeps every existing config; `by_agent` gives each step its own reply without spelling out a rendered task | two steps on one agent share a `by_agent` reply | *observed*: `test_the_mock_replies_by_task_then_by_agent_then_by_default` |
| `matrix runs` lists runs from the store alone; `matrix run` prints the record's files from the store's own `tables` | compose the whole config first | listing a store needs no runtime: a config whose runtime lacks its extra still lists its runs | the file lines appear only for a store whose tables name files (JSONL) | *observed*: `test_run_names_the_files_of_its_record_and_runs_lists_them` |
| Model names live in each runtime's config-schema description (so `describe` shows them), the skill and the `agents` reference | a registry field for models | the values are the backend's (the Claude Code CLI's aliases, a hardline registry's names); a description says where they come from without matrix keeping a list that would go stale | the aliases named (`haiku`, `sonnet`, `opus`) are those the installed SDK's own comment names; full ids are the SDK docstring's examples, not a catalogue | *observed*: `test_describe_says_which_models_each_runtime_takes` |
