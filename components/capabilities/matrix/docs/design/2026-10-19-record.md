# matrix 0.6.0: design record, 2026-10-19

The judgments made building matrix 0.6.0, recorded by the crafting-aces procedure (its
`SKILL.md`, and `references/ports-and-adapters.md`, `interface.md`, `composition-root.md`).
Rows take the skill's form: claim, test, verdict, named weakness or measure, evidence.
Evidence tags: *observed* (read or run on this tree today), *reported* (a dated document),
*inferred*, *hypothesis*. "The audit" is
`scratch/research-matrix-ix-landscape/2026-10-19/cli-api-audit.md` (reported).

Provenance carried from the skill: the ports-and-adapters layout rests on one author and one
adopting study; the composition root driven by configuration is the ACES framework's
practice, not the canon's; stasis, drag and opacity are that framework's model. Nothing here
is called ACES compliant except as a claim in four parts.

## 13. Agent runtimes and model runtimes, split (2026-10-22)

One port, one registry point and one reply type had carried two conversations: an agent
session (a loop, tools, turns) and one model call through hardline (*reported*:
`scratch/review-2026-10-22/matrix.md`, area 4). The port's own docstring named the mismatch:
`check` existed to refuse "a single-call runtime handed tools". The model runtime's `check`
refused definitions the claude-sdk runtime's accepted, a strengthened precondition, so it was
no substitute under interface D24 (Liskov and Wing); and it filled `num_turns=1` and
`stop="completed"` with constants, so a truncation or a refusal could never show, while the
facts a call does have (request id, attempts, fallback) had no slot. yzavyas ruled the split
(Q5, and the Phase 4 design of `scratch/PLAN-2026-10-22-final-components.md`).

## 14. Provenance: what a call and a session carry (2026-10-22)

A model's reply is a sample, so a reader of the record must be able to tell which model gave
it, how, and whether it is a whole answer. The review found matrix keeping part of what its
runtimes reported and stamping constants over the rest (*reported*:
`scratch/review-2026-10-22/matrix.md`, area 3; `full/matrix-src.md` F9, F10, F30;
`full/matrix-tests.md` findings 4 and 11). hardline 0.2 now reports a call's whole record
(its `docs/design/2026-10-22-record.md`), and this section records how matrix carries it.

| decision | alternatives weighed | verdict and why | named weakness | evidence |
|---|---|---|---|---|
| `ModelCall` carries hardline's whole record: `finish_reason` (hardline's vocabulary, as matrix's own `FinishReason`), `native_finish_reason`, `refusal`, `params`, `attempt_log`, `turns_digest` and `row` (digest and rungs), beside the answering model, `fallback_from`, usage with cache tokens, `request_id`, `attempts`, `retries` and latency | keep the fields matrix had; import hardline's types into the domain | a fact hardline knew and matrix dropped had no other home (area 3); the domain names no outside technology, so the vocabulary and the record's shapes are matrix's own, mapped in the adapter | the adapter maps field by field: a field hardline adds is dropped until the adapter maps it | *observed*: `test_a_call_carries_hardline_s_whole_record`, `test_a_fallback_is_recorded_as_the_model_that_answered` |
| `usage`, `attempts`, `retries` and `latency_ms` default to `None`, as every other fact of a call does | keep zeros and `attempts=1` | a default of 0 or 1 is a constant standing in for a fact the runtime did not report (RQ6 T3; mx-tests 4) | a consumer that summed them must say what an unreported value counts as (ix's adapter keeps 0, as before) | *observed* |
| The `mock` model runtime reports what is true of a canned reply: one attempt, no retries, zero tokens, the time it took, `finish_reason: stop` | report nothing | a canned reply is exactly what was configured, so it is whole, and it spent no tokens; it reports no cost, which only a provider can | a mock cannot plant a cut or refused reply; hardline's `mock` backend can (`finish_reason`, `refusal` options) | *observed*: `test_the_mock_model_replies_by_prompt_then_by_model_then_by_default` |
| **A model step fails on a reply that is not a whole answer**: a `refusal`, a `finish_reason` other than `stop` and `None`, or empty text. `ModelRuntimeError`, reason `refused` (a refusal, `content_filter`) or `failed` (`length`, `tool_call`, `other`, empty), kind `component`, with the finish reason in its details and a fix for that reason | provide the row and let it carry the reason | a component that requires the kind takes any row it is given as an answer, and the wiring has no way to say "whole answers only", so a row that carries the reason still looks like an answer to everything downstream (RQ6 T3, T19). Failing is loud, and the error names the finish reason; a caller that wants to study refusals calls the port itself, as ix's `model-call` subject does | a pipeline that wanted a cut reply has to raise `max_tokens` or call the port; neither reason is retried, since a second identical call is likely to end the same way | *observed*: `test_a_reply_that_is_not_a_whole_answer_fails_the_step_saying_why` |
| A `finish_reason` of `None` is not taken as a cut reply | treat unknown as not whole, as hardline's `answered` does | a third-party runtime whose provider says nothing would fail every step, and the record keeps the `None` for a reader to see | an unknown ending passes | *observed*: `test_a_whole_answer_or_one_whose_runtime_does_not_say_is_the_reply` |
