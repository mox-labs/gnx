# matrix 0.10.0: design record, 2026-11-06

The judgments made building matrix 0.10.0, step 3 of the component fix-up: the model-runtime
seam, the bridge that carries hardline across it, and extension discovery. Rows take the form
of the earlier record (`2026-10-19-record.md`): decision, alternatives weighed, verdict and
why, named weakness, evidence. Evidence tags: *observed* (read or run on this tree today),
*reported* (a dated document), *inferred*. "The decisions" is the fix-up's decision sheet
(`DECISIONS-components-2026-11-06.md`, rulings G1 to G7, M-O1 to M-O8, HO1 to HO9, M-DISC);
"the hardline review" and "the matrix review" are `REVIEW-hardline-2026-11-06.md` and
`REVIEW-matrix-2026-11-06.md`, all kept outside the repository (*reported*).

This record supersedes, in the earlier one: §14's field-by-field map of hardline's record onto
`ModelCall` and the session row; §18's pydantic-ai runtime built on hardline and its
`usage_counted_by`; §19's `pydantic_ai_model` as an optional member of the port.

## 1. The model-runtime seam (rulings HO1, M-O1 to M-O3, M-O5, M-O6, M-DEP)

| decision | alternatives weighed | verdict and why | named weakness | evidence |
|---|---|---|---|---|
| **matrix depends on no model runtime.** hardline leaves matrix's dependencies; no module of matrix imports it; the layer map forbids it in every layer. The adapter is a separate distribution, `matrix-hardline`, which depends on matrix and hardline and registers from its own `matrix.extensions` entry point | (c) matrix keeps the dependency and one seam module (the hardline review's recommendation); (b) hardline depends on matrix and holds the adapter; (d) a shared contract package | the owner ruled (c′) on 2026-11-06 ("wack architecture"). The review's stated cost of (c′), "matrix would ship with no real model runtime, so a user must know to install it", is answered by §1's refusal row below and by ix depending on the bridge, so `ix` works as installed | a user of matrix alone gets no model runtime that calls a model; the fix names the one this repository ships | *observed*: `tests/test_architecture.py::test_matrix_depends_on_no_model_runtime` |
| **The port is one call in full**: `ModelRequest(turns, model, tools, output, max_tokens, temperature)`; `ModelRequest.from_prompt(prompt, system=...)` builds a prompt's one user turn; `check(model, *, uses=frozenset())`, `uses` a set of `tools` and `output` | keep the prompt-only request and add a framework-model member (what `pydantic_ai_model` was); a second "chat" port; keep a `system` field beside the turns | the narrow port buried the power of the layer below (the matrix review, D-3, HBL:c37), and the first agent runtime that needed it went round the port. Turns, tools and the two overrides are what every chat-completion provider takes. A system prompt is a turn: one shape, not two. `uses` is an enum set a caller sends, so it can gain values (AP:c40) | text only: an image or a document has no turn yet (the matrix review's falsifier 3) | *observed*: `tests/test_pydantic_ai_runtime.py::test_an_agent_s_loop_runs_on_a_model_runtime_through_the_port` |
| **The reply is neutral; what one runtime alone knows is a typed document keyed by its type URL**, `ModelCall.provenance: dict[type URL, JSON]`, and the session row's `provenance` the same. `backend`, `attempts`, `retries`, `fallback_from`, `params`, `attempt_log`, `turns_digest`, `row` and the types `RequestParams`, `CallAttempt`, `RegistryRow` are gone | one `provenance` value with a `type_url` field (the matrix review's R3.2 wording); hardline's fields as columns (as before) | keyed by type URL, a reader dispatches on the key (`jq '.provenance["hardline.v1.call"]'`) and a call may carry more than one runtime's document (a wrapper's beside its inner runtime's). A runtime's record grows in its own document, under its own major, and never in matrix's record (D-2; "ports don't grow by feature") | a query that read `fallback_from` as a column reads JSON now; DuckDB reads it with `->>` | *observed*: `tests/test_sessions.py::test_a_failed_model_call_is_still_a_session_row_with_what_it_cost` |
| **A provenance document is validated against the schema registered for its type URL** when the session row is recorded (the executor's `record_session`); a document the schema refuses is a `ContractError` and the row is not recorded. A key must be a versioned type URL, checked when the `ModelCall` is built | validate only at the producer; refuse a document whose type URL has no registered schema | "validated by a payload schema the runtime's package registers" (the matrix review, R3.2) is a claim the record can keep only if matrix checks it. Refusing an unregistered one would fail every run wired without the registry's schemas (a test's `wire({...})`), so an unregistered document is kept as it is, as a kind without a schema is | a runtime that registers no schema is unchecked | *observed*: `tests/test_sessions.py::test_a_session_s_provenance_is_held_to_the_schema_registered_for_its_type_url` |
| **The bridge's runtime is `matrix-hardline.v1.model-runtime`**, under the bridge's own namespace. hardline's record is under hardline's, `hardline.v1.call`, registered by the bridge on hardline's behalf (hardline imports nothing of matrix, HO2). What a failed call carries is the bridge's own document, `matrix-hardline.v1.failed-call` | keep `matrix.v1.model-runtime.hardline` (short name `hardline`), which every config, ix test and stored row named; `hardline.v1.model-runtime`, on hardline's behalf | a type URL in matrix's namespace for a runtime matrix does not ship is the privilege the ruling removes, and the namespace rule (a distribution owns its own root, G7) says whose it is. The failed-call document is the bridge's composition of hardline's error fields, so it is the bridge's. hardline's `CallRecord` is hardline's document, whole | every config moves to the full type URL; the bridge's name is provisional, and a rename moves its type URLs, which are stored in session rows (a one-way door) | *observed*: `matrix-hardline/tests/test_bridge.py::test_it_registers_its_runtime_and_the_schemas_of_what_it_records` |
| **With no model runtime that calls a model installed, a config that names one is refused when it is composed**, and the fix names what to install (`pip install matrix-hardline`, `matrix-hardline.v1.model-runtime`). The pointer is one constant in the composition root, said only when every installed model runtime is a stand-in | a default runtime in matrix; nothing (the generic "install the package providing it") | a refusal at `matrix check`/`plan`, before anything runs, never a late crash. It is a pointer, not a branch: no behaviour depends on it | the constant names the bridge in matrix's root; it is text, and the layer test holds the code to no import | *observed*: `tests/test_composition.py::test_unknown_model_runtime_type_lists_the_registered_model_runtimes` |
| **The pydantic-ai runtime takes a model runtime by name**, `model_runtime` (required: which runtime answers is the operator's choice, and no value is safe to assume), and registers the need `model_runtimes`. Composition builds model runtimes first and hands them to agent runtimes | nest a model runtime's config in the agent runtime's; default to the only model runtime configured | the uses graph is agent runtime, then model runtime, then provider, loop-free (PM:c41); a nested config would build a second instance of what `model_runtimes` already holds. A default by count would change meaning when a second model runtime is added | `model_runtime` has no default, which G2's letter asks of every key; a required key that is refused, with the names that exist, is the safe reading | *observed*: `tests/test_pydantic_ai_runtime.py::test_a_model_runtime_it_names_must_be_composed` |
| **`usage_counted_by` goes; composition knows.** An agent runtime that declares the need `model_runtimes` makes its calls on them; `BoundAgent(..., through_model_runtime=True)` puts `through_model_runtime` on `matrix.agent.end`, and the `otel` observer counts none of that session's tokens | keep the name read by `getattr`; a registration field | the fact is composition's (it wired them), as the matrix review's R3.6 says, and the need is already declared at registration, so no new field is needed. A runtime that declares the need and makes calls elsewhere would be counted by no one: the need's summary says what declaring it means | an agent runtime that makes calls on a model runtime without declaring the need is counted twice, as before | *observed*: `tests/test_pydantic_ai_runtime.py::test_matrix_counts_no_token_of_a_session_made_on_a_model_runtime`, `matrix-hardline/tests/test_bridge.py::test_a_session_s_tokens_on_hardline_are_counted_once` |
| **`pydantic_ai_model(runtime, model, *, settings, runtime_url, drives)` is public (M-O6)**, over any `ModelRuntime`; each call is a session row as a model step's is. It refuses any pydantic-ai setting but `max_tokens` and `temperature` (M-5): a `ConfigError` when given as `settings`, else at the request that carries it, before anything is sent | an optional member of the port (as before); drop unknown settings silently (as before) | a framework's type in a port is the defect the matrix review named; the function depends on the port, not the reverse. A dropped setting deceives the caller (AP:c10). The judge's call and a step's call now digest one request form, so equal requests have equal `sent` | the port's two overrides are all any setting can become (HO7); a caller that wants `top_p` gets a refusal, not the setting | *observed*: `tests/test_pydantic_ai_runtime.py::test_a_setting_a_model_call_cannot_carry_is_refused_never_dropped`, `::test_each_call_the_pydantic_ai_model_makes_is_a_session_row_as_a_steps_is` |
| **`ModelRuntimeConformance` in `matrix.testing`**: it keeps the port, `check` takes the model and `uses` and refuses a name it cannot resolve, a call ends in a `ModelCall` or a classified failure, and each optional member keeps its protocol | none, as 0.9 said ("there is none for the model-runtime port"), because the seam was changing | the seam is settled in this release, so the reason for having none is gone; the bridge, the mock and the tests' stand-ins run it | a suite proves behaviour on one call; it cannot prove a runtime carries every part of a request | *observed*: `tests/test_conformance.py::TestTheMockModelRuntime`, `matrix-hardline/tests/test_bridge.py::TestTheBridgeKeepsThePort` |

**The falsifiers, checked.** The hardline review's D1 falsifier (2), "the adapter cannot be
written without matrix's domain naming a hardline type", did not fire: matrix's domain names
none, and the adapter reaches matrix and hardline only through their `__all__`
(`matrix-hardline/tests/test_bridge_layering.py`). The matrix review's R3 falsifier (1), "a second
model runtime cannot serve the pydantic-ai runtime through the widened port without a new
port member", did not fire: the pydantic-ai runtime's whole loop, tool calls and failures
included, runs on a stand-in written against the port alone (`tests/test_pydantic_ai_runtime.py`'s
`Scripted`) and on matrix's mock, and an ix judge evaluator runs on a third party's model
runtime that never heard of pydantic-ai (`ix/tests/test_evaluators.py::test_any_model_runtime_can_judge`).
