# hardline 0.2: design record, 2026-10-22

The judgments made building hardline 0.2 (stage 4a of the final-components plan), recorded by
the crafting-aces procedure (its `SKILL.md`, and `references/ports-and-adapters.md`,
`interface.md`, `composition-root.md`). Rows take the skill's form: claim, test, verdict, named
weakness or measure, evidence. Evidence tags: *observed* (read or run on this tree today),
*reported* (a dated document), *inferred*, *hypothesis*. "The review" is the independent
review of hardline of 2026-10-22, a first pass and a full read, *reported*; it is kept outside
this repository, so each row restates the finding it relies on.

The owner's rulings this record relies on, each stated here since the plan that holds them is
not in the repository (the ids are the plan's, kept so later records can cite them):

- **Q3** (owner ruling, 2026-10-22): matrix gains a `pydantic-ai` agent runtime in this release.
- **Q5** (owner ruling, 2026-10-22): agent runtimes and model runtimes stay distinct ports in
  matrix, and nothing branches on a runtime's name.
- **Q8** (owner ruling, 2026-10-22): hardline's built-in backends register through its own
  `hardline.backends` entry points, not a table; it moves to slick's registry later, like the
  other packages.
- **Q9** (owner ruling, 2026-10-22): hardline's CLI moves from argparse to rich-click, the
  workspace's one stack.
- **Q10** (owner ruling, 2026-10-22): `openai_compat` is written directly on HTTP and the
  `openai` SDK is dropped.
- **Q12** (owner ruling, 2026-10-22): the HTTP library is httpx2, and each migration first checks
  redirects, timeouts, MockTransport and `truststore` (§5).
- **Q13** (owner ruling, 2026-10-22): no package has optional extras, and hardline speaks both
  protocols on httpx2 with no provider SDK; this supersedes the anthropic half of Q10.

This is hardline's first design record. Nothing here is called ACES compliant except as a claim
in four parts.

### Rearrangements a caller must not notice

What composing hardline inside a host (matrix's model step and `pydantic-ai` runtime, ix's
judge and `model-call` subject) relies on, written as requirements: each rearrangement below is
a configuration change, and a caller that asks for the same row by name makes the same call and
gets a `Completion` that names the row, backend, model and family that answered. Each is held
by the test named.

| rearrangement | requirement | test |
|---|---|---|
| the backend behind a row is replaced (a local server for a hosted one, one protocol for the other) | the caller's call is unchanged; the row's location is the row's, whatever the environment | `test_a_row_without_base_url_goes_to_its_backends_default_whatever_the_environment` |
| a fallback is inserted, removed or reordered | the caller's call is unchanged; the `Completion` names the row that answered and `fallback_from`, and `attempt_log` each row tried | `test_fallback_answers_and_the_completion_names_who_answered`, `test_the_attempt_log_names_each_row_tried_and_why`; in matrix, `test_a_fallback_is_recorded_as_the_model_that_answered` |
| a backend is installed, or a broken one appears | no edit to hardline; only the rows naming a broken one fail | `test_entry_point_backend_is_discovered`, `test_a_broken_backend_plugin_fails_only_the_rows_naming_it` |
| the secret resolver is swapped | the runtime resolves the row's reference through whichever it is given, and hands the backend the key alone | `test_a_backend_is_told_where_and_how_to_send_and_nothing_of_the_runtimes_policy` |
| the configuration source is swapped, or a host hands its own `models` section | the same rows compose, and each field's tier is recorded | `test_mapping_source_is_how_another_root_hands_its_section`, `test_the_record_names_the_row_its_digest_and_the_tier_of_each_field` |
| a tier is added above another | it overrides field by field, never row by row | `test_later_tier_overrides_field_by_field` |
| the observer is swapped | the call is unchanged; an observer that raises is logged, never the call's failure | `test_an_observer_that_raises_does_not_fail_the_call` |

Not tolerated, so a caller notices: renaming a row it asks for by name (a `ConfigError` listing
the known names), and changing a row's `family` (recorded on every `Completion`, since a judge
reads it).

**Fewer than three independent implementations (W8.3).** `ModelBackend` has three: the
OpenAI-compatible and Anthropic protocols and the mock, all hardline's own and one a test
double, so the rule of three (review row 6) is not met. No third party has written a backend
yet. What a third one needs is the contract in a form it can run, so hardline ships it:
`backend_problems` and `answer_problems` (`conformance.py`), which every installed backend
passes (`test_hardline_conformance.py`). The seam is trusted on that check and on two protocols
unlike each other, not on independent authors.

**What crosses `ModelBackend` is an `Endpoint`, not the `ModelSpec`** (boundary test 7). The
whole row showed every backend the runtime's retry, fallback and limit policy, the row's family
and where its key lives: decisions the runtime hides (§2), which a backend could come to read.
An `Endpoint` holds what one attempt needs: the row's name and backend for messages, `model`,
`provider`, `base_url`, `proxy`, `timeout_s`, `structured`, `options`, and `has_key`, whether the
row names a key, which a backend that cannot run without one checks at composition. The key
itself is resolved by the runtime and handed to each call. `ModelSpec.endpoint()` makes one;
`answer_problems` still takes a row, as an author writes one.

## 5. httpx2, checked before use (Q12)

The owner's ruling asks each migration to check redirects, timeouts, MockTransport and
`truststore` first. Checked against httpx2 2.10.0's source in the workspace lock, and by a
probe against a loopback server, 2026-10-22 (*observed*):

| behaviour | what httpx2 does | what hardline does, and why |
|---|---|---|
| timeouts | `DEFAULT_TIMEOUT_CONFIG = Timeout(timeout=5.0)` (`_config.py:247`), for each of connect, read, write and pool; a slow read raises `ReadTimeout`, a `TimeoutException` | sets `Timeout(timeout_s)` on every client, since 5 s is far below a model's reply time; a `TimeoutException` is `timeout`, any other `TransportError` is `unavailable` (`test_each_built_in_has_a_timeout_of_its_rows_choosing`, `test_transport_failures_are_transient`) |
| redirects | not followed by default (`follow_redirects: bool = False`, `_client.py:1471`); a 307 comes back as the response, `is_redirect` true | kept, and reported: a `ConfigError` whose fix names the `base_url` the `Location` implies, since following would send the key along (`test_a_redirect_is_reported_not_followed`) |
| MockTransport | `httpx2.MockTransport` (`_transports/mock.py:15`) takes a sync or async handler, sees the full request, and raises what the handler raises | each backend takes `transport=`; the adapter tests run on it, and the workspace guard refuses the real transport (`network_transport`) in every test |
| TLS | `create_ssl_context` uses `truststore.SSLContext`, the operating system's store, unless `trust_env` and `SSL_CERT_FILE`/`SSL_CERT_DIR` are set (`_config.py:23-40`); httpx used certifi's bundle | `trust_env=False` everywhere, so the system store always, and no certificate variable applies. An `https://` proxy is handed `create_ssl_context(trust_env=False)` too: given none, httpcore2's `default_ssl_context()` reads `SSL_CERT_FILE` and `SSL_CERT_DIR` whatever `trust_env` says (`test_an_https_proxy_is_verified_against_the_system_store_whatever_the_environment`) |
| environment | `trust_env=True` by default: proxy variables mount proxies when no transport is given (`_client.py:1503`), and the TLS variables above apply | `trust_env=False` on the client and the transport: no proxy variable reroutes a request. A row's own `proxy:` is the transport's `proxy=` |
| retries | `AsyncHTTPTransport(retries=0)` by default (`_transports/default.py:286`), connection retries only; no status is retried | `retries=0` passed explicitly; the runtime's `retries` is the only policy (`test_no_retry_hides_behind_the_runtimes_own`) |
| base URL joining | `base_url` path and request path merge: `.../v1` + `chat/completions` is `.../v1/chat/completions`, with or without a trailing slash | the SDKs' conventions are kept, so existing rows work unedited: OpenAI-compatible `base_url` includes `/v1`, Anthropic's does not |

## 7. Choices made in this stage

- **A proxy is a row field** (`proxy:`, W7.10), recorded like `base_url`: `trust_env=False`
  removes the environment's route, and a user behind a proxy names it. A proxy URL with
  credentials is refused rather than read from a reference: no consumer has an authenticated
  proxy yet, and refusing keeps a password out of every config file.
- **A redirect is a `ConfigError`** (W7.10), raised by the adapter that saw it, with a `fix`
  naming the `base_url` the `Location` implies. It is not a `BackendError`: nothing about it is
  transient, and no fallback should hide it. It is therefore not in `attempt_log`, although the
  request was sent.
- **`answered` is a property, not a field.** A computed field would be serialised, and
  `Completion` is `extra="forbid"`, so re-validating its own JSON would fail. JSON readers get
  the three facts it is computed from.
- **The keyless OpenAI-compatible row sends no `Authorization` header.** The SDK needed a
  placeholder; without the SDK there is nothing to placate.
- **The Anthropic API version is fixed** at `2023-06-01` in the adapter, the version its body
  shape is written against.
- **The version is 0.2.0, the version it will be released as.** matrix requires
  `hardline>=0.2,<0.3`; the bump and matrix's bound moved together, in stage 4b.

  with no text (a text block's `text` has a minimum length of 1, platform.claude.com/docs/en/api/messages,
  read 2026-10-22), so an echoed empty reply turned a schema failure into a 400. The repair turn
  says the reply was empty instead, and the `anthropic` adapter leaves out any assistant turn with
  neither text nor tool calls; the API combines the user turns either side into one.
- **The backoff constants are written down with their reasons** (W10.1, review step 7's T5
  weakness): a 0.5 s first wait, doubling capped at 8 s so one row's waits stay under a minute,
  and a provider's Retry-After honoured up to 60 s. They are fixed, where `retries` is per row,
  because they describe providers rather than rows; `limits.seconds` now bounds every wait.
- **The limits belong to the row asked for**, not to each row tried. A fallback chain is the
  requested row's policy, so its bound is too; a fallback's own `limits` bound a call that asks
  for it by name.
- **A limit raises the error the call would have raised**, with `limit` set: no new `Reason`,
  so a caller's handling of a transient failure, and the CLI's exit codes, are unchanged.
- **The in-flight cut uses the event loop's clock** (`asyncio.timeout`), the checks between
  calls the runtime's injected clock. Both are monotonic, and with the default clock they agree.

- **`arguments` is the JSON text the model wrote, not a parsed object.** A model's arguments can
  fail to parse; parsed, that reply would have to be refused, and the caller could not tell the
  model what it got wrong (pydantic-ai's tool loop does exactly that). The Messages API's object
  is written as JSON text when read.
- **The turns digest grows a third element only for a turn with tool parts**, so every digest a
  reader computed before is unchanged.
- **Tools are offered by `complete` alone.** `extract` states a schema and validates a reply; a
  call that both asks for tools and must return a structure has no single meaning of "answered".
- **`params.tools` names the tools offered, not their schemas.** The names say what was offered;
  a changed schema under the same name is not told apart.
