# hardline 0.2: design record, 2026-10-22

The judgments made building hardline 0.2 (stage 4a of the final-components plan), recorded by
the crafting-aces procedure (its `SKILL.md`, and `references/ports-and-adapters.md`,
`interface.md`, `composition-root.md`). Rows take the skill's form: claim, test, verdict, named
weakness or measure, evidence. Evidence tags: *observed* (read or run on this tree today),
*reported* (a dated document), *inferred*, *hypothesis*. "The review" is
`scratch/review-2026-10-22/hardline.md` (first pass) with
`scratch/review-2026-10-22/full/hardline-and-workspace.md` (the full read), both *reported*.
The owner's rulings Q8, Q10, Q12 and Q13 are in `scratch/PLAN-2026-10-22-final-components.md`.

This is hardline's first design record. Nothing here is called ACES compliant except as a claim
in four parts.

**Fewer than three independent implementations (W8.3).** `ModelBackend` has three: the
OpenAI-compatible and Anthropic protocols and the mock, all hardline's own and one a test
double, so the rule of three (review row 6) is not met. No third party has written a backend
yet. What a third one needs is the contract in a form it can run, so hardline ships it:
`backend_problems` and `answer_problems` (`conformance.py`), which every installed backend
passes (`test_hardline_conformance.py`). The seam is trusted on that check and on two protocols
unlike each other, not on independent authors.

`ModelSpec` still crosses the port whole, so every backend sees the runtime's retry and fallback
policy (review row 2, boundary test 7). Narrowing it is a change to the port and every backend,
and was not part of this stage.

## 5. httpx2, checked before use (Q12)

The owner's ruling asks each migration to check redirects, timeouts, MockTransport and
`truststore` first. Checked against httpx2 2.10.0's source in the workspace lock, and by a
probe against a loopback server, 2026-10-22 (*observed*):

| behaviour | what httpx2 does | what hardline does, and why |
|---|---|---|
| timeouts | `DEFAULT_TIMEOUT_CONFIG = Timeout(timeout=5.0)` (`_config.py:247`), for each of connect, read, write and pool; a slow read raises `ReadTimeout`, a `TimeoutException` | sets `Timeout(timeout_s)` on every client, since 5 s is far below a model's reply time; a `TimeoutException` is `timeout`, any other `TransportError` is `unavailable` (`test_each_built_in_has_a_timeout_of_its_rows_choosing`, `test_transport_failures_are_transient`) |
| redirects | not followed by default (`follow_redirects: bool = False`, `_client.py:1471`); a 307 comes back as the response, `is_redirect` true | kept, and reported: a `ConfigError` whose fix names the `base_url` the `Location` implies, since following would send the key along (`test_a_redirect_is_reported_not_followed`) |
| MockTransport | `httpx2.MockTransport` (`_transports/mock.py:15`) takes a sync or async handler, sees the full request, and raises what the handler raises | each backend takes `transport=`; the adapter tests run on it, and the workspace guard refuses the real transport (`network_transport`) in every test |
| TLS | `create_ssl_context` uses `truststore.SSLContext`, the operating system's store, unless `trust_env` and `SSL_CERT_FILE`/`SSL_CERT_DIR` are set (`_config.py:23-40`); httpx used certifi's bundle | `trust_env=False` everywhere, so the system store always, and no certificate variable applies |
| environment | `trust_env=True` by default: proxy variables mount proxies when no transport is given (`_client.py:1503`), and the TLS variables above apply | `trust_env=False` on the client and the transport: no proxy variable reroutes a request. A row's own `proxy:` is the transport's `proxy=` |
| retries | `AsyncHTTPTransport(retries=0)` by default (`_transports/default.py:286`), connection retries only; no status is retried | `retries=0` passed explicitly; the runtime's `retries` is the only policy (`test_no_retry_hides_behind_the_runtimes_own`) |
| base URL joining | `base_url` path and request path merge: `.../v1` + `chat/completions` is `.../v1/chat/completions`, with or without a trailing slash | the SDKs' conventions are kept, so existing rows work unedited: OpenAI-compatible `base_url` includes `/v1`, Anthropic's does not |

## 7. Choices made in this stage

- **A proxy is a row field** (`proxy:`, W7.10), recorded like `base_url`: `trust_env=False`
  removes the environment's route, and a user behind a proxy names it. A proxy URL with
  credentials is refused rather than read from a reference: no consumer has an authenticated
  proxy yet, and refusing keeps a password out of every config file.
- **A redirect is a `ConfigError`** (W7.10), raised by the adapter that saw it, with a `fix`
  naming the `base_url` the `Location` implies. It is not a `BackendError`: nothing about it is
  transient, and no fallback should hide it. It is therefore not in `attempt_log`, although the
  request was sent.
- **`answered` is a property, not a field.** A computed field would be serialised, and
  `Completion` is `extra="forbid"`, so re-validating its own JSON would fail. JSON readers get
  the three facts it is computed from.
- **The keyless OpenAI-compatible row sends no `Authorization` header.** The SDK needed a
  placeholder; without the SDK there is nothing to placate.
- **The Anthropic API version is fixed** at `2023-06-01` in the adapter, the version its body
  shape is written against.
- **The version is 0.2.0, the version it will be released as.** matrix's `models` extra
  requires `hardline>=0.2,<0.3`; the bump and matrix's bound moved together, in stage 4b.

## 11. Failure bounds (phase 5, W6.1)

| claim | test | verdict | named weakness or measure | evidence |
|---|---|---|---|---|
| R(hardline, *a logical call costs no more than its row allows*, W = retries, fallbacks and schema repairs in any mix, M = backend calls, seconds or tokens past the row's `limits`) | stress T34, T17; RQ5 T19; review rows 16 and 21 | holds with a named weakness | M = 0 calls past `attempts`; no wait started that would pass `seconds`, and a running attempt cut when it does; tokens are checked between calls, so the call that crosses `tokens` completes. Every limit is unset by default: the default bound is still the chain's, (repairs + 1) × Σ(retries + 1). The defaults are the owner's to choose | *observed*: `test_limits_*`, `test_no_limits_means_the_bound_is_the_chain_and_the_repairs` |
| A schema repair never restarts at a row that has just failed | review row 15 | holds | a repair still moves on down the chain when the row that answered then fails transiently, so a conversation can still hold two models' replies, in chain order | *observed*: `test_a_schema_repair_goes_on_from_the_row_that_answered` |
| A fallback that shares its primary's server is said to (W6.2) | stress T34, T35; review row 18 | holds with a named weakness | "shares" is the same backend and `base_url`. Two rows on different URLs of one host, or behind one proxy, share fate unseen; a row with no location (the mock) shares none. It is a warning, not a refusal: the row is legal, and guards against a failing model | *observed*: `test_a_fallback_on_the_same_server_as_its_primary_is_warned_of`, `test_cli_check_reports_a_fallback_that_shares_its_primarys_fate` |
| A failure no retry can change is not retried | review row 19 | holds with a named weakness | 501 and 505 are `bad_request`. A 500 that a prompt reproduces every time is still retried and fallen back from: a server's fault is more often passing, and `limits` bounds what a reproducible one costs | *observed*: `test_both_protocols_classify_a_status_alike` |

- **The backoff constants are written down with their reasons** (W10.1, review step 7's T5
  weakness): a 0.5 s first wait, doubling capped at 8 s so one row's waits stay under a minute,
  and a provider's Retry-After honoured up to 60 s. They are fixed, where `retries` is per row,
  because they describe providers rather than rows; `limits.seconds` now bounds every wait.
- **The limits belong to the row asked for**, not to each row tried. A fallback chain is the
  requested row's policy, so its bound is too; a fallback's own `limits` bound a call that asks
  for it by name.
- **A limit raises the error the call would have raised**, with `limit` set: no new `Reason`,
  so a caller's handling of a transient failure, and the CLI's exit codes, are unchanged.
- **The in-flight cut uses the event loop's clock** (`asyncio.timeout`), the checks between
  calls the runtime's injected clock. Both are monotonic, and with the default clock they agree.
