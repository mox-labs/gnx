# Changelog — recon

## Unreleased

### The skill

- **Every kind is listed by `recon --skill -r errors`** (`docs/reference/errors.md`, the same text): the error kinds, the problem kinds and the warning kinds, each list in the code's order. `recon --skill` keeps the exit-code table (every error kind, what it means, what to do next), what a problem record holds, and one line pointing to the reference, so the skill stays within its 30,000-character budget with this round's keys.

### Pagination

- **`paginate:` on an `api` collector reads its source page by page** into one table: `{type: link | header | cursor | offset | page, pages: 100, next, param}`. `link` follows the URL at the body path `next`, `header` the `Link` header's `rel="next"`, `cursor` sends the value at `next` as the query parameter `param`, `offset` sends the records read so far as `param`, `page` the page's number from 1 (the first page's too); each type needs the keys it reads and takes no other. Every page is a request through the requester, so it draws a rate-limit token, is retried as any request is, and is captured with `preserve_raw`. A next page off the source's origin (scheme, host, port) fails the table, `run_failed`: the source's credential would go with it. The contract: `docs/reference/pagination.md`, which `recon --skill -r pagination` prints.
- **Every stop is recorded.** No next token is the end (and an `offset` or `page` page with no records). `pages` pages read with more to read, a token the crawl used already (any earlier one, not only the last), or three empty pages in a row that still link on stop the crawl: the table is sealed `ok` and `truncated`, its outcome says `truncated: true` and `truncated_by` (`pages`, `loop`, `empty`), and the survey warns `page_cap`, `paginate_loop` or `paginate_empty`, new problem kinds, each with a fix. A page a loop names is not asked for again.
- **Each record of a paginated table carries `_position`, `{page, i}`**, and the table's page log, `<output>.pages.jsonl`, keeps each page's token once (a URL with the source's `auth.param` redacted), written once the table is sealed; it is no table. A page's capture names its `page`, so a `capture` collector reading a crawl's captures gives each record the same `_position` and the table replays byte for byte.
- **The plan reports the crawl**: the run's `paginate`, `provenance` entries for `collectors.<i>.paginate.pages` (its origin) and, for each run, `collectors.<i>.paginate.floor_s`, the least seconds the crawl takes at its source's rate limit, `(pages - burst) / rps`, against the deadline that bounds its table; and a `deadline_short` warning, a new problem kind, when that deadline is shorter. It refuses `paginate:` on a type that does not declare `paginates` and on a stream, a type's missing or extra key, a `normalize:` column named `_position`, a `params:` key the crawl sends, and an output named as a page log (`<name>.pages`).
- **A collector type of your own may paginate**: `CollectorType.paginates`, `CollectorContext.pages` (a `PageLog`), and `recon.domain.paginate` (`PaginateSpec`, `Crawl`, `position`), as `docs/reference/extending.md` says.
- **The `ArchiveStore` port gains `write_sidecar` and `read_sidecar`**, what a table keeps beside it that is no table (its page log); a store of your own given to `root()` implements them, and leaves a sidecar out of `tables()`.

### One credential grammar for every source

- **Breaking: `auth.env: NAME` is `auth.token: env:NAME`.** An `api` or `sse` source names its credential as an `mcp` source does: `auth.token` is `env:NAME` (a variable) or `file:PATH` (a file, relative to the mission's directory), sent as `auth.header` and/or `auth.param` with `auth.prefix`; or `auth.headers_helper` names a command, run once a survey within the source's `timeout`, whose standard output is a JSON object of the headers to send. A token written as the secret itself, a token with a helper, and a helper with `header`, `param` or `prefix` are plan problems; `auth.env` is now an unknown key, and the problem's `allowed` names `token`. So a survey run unattended gets its credential without a secret in its environment. Removed before 1.0, with no alias.
- **A `file:` its group or others can read is refused**, for every source kind (an `mcp` source's `token: file:` too): the table fails as `config`, before anything is sent, with the `chmod 600` that fixes it.
- **One resolver**: `recon.adapters._out.credentials` (`resolve_reference`, `helper_headers`, `Credentials`) is what the `api`, `sse` and `mcp` collectors use, and what a type of your own may use. `ApiCollector` and `SseCollector` take a `Credentials` where they took the environment.
- **Every header a collector gives, but `User-Agent`, `Accept`, `Cache-Control` and `Last-Event-ID`, stays at its request's origin**: a redirect to another host, port or scheme drops it, a helper's headers included, whose names recon cannot know in advance (it dropped only the source's `auth.header`).
- The plan's `env_unset` warning for an `api` source is at `catalog.<i>.auth.token`, and the `auth` exit kind's next step names `auth.token` and `headers_helper`.

### Change detection

- **`changes: {key: [field, ...], volatile: [], deletes: false}` on a collector entry** compares each table it writes with the **told index**, the fold of every change row told for its output and source (the previous table's, the latest compared in a survey that ran to its end; a truncated table tells its inserts and updates, a failed or stopped one tells nothing), and writes what changed as the table `<output>.changes` (SQL: `<output>_changes`): rows `{op, key, record}`, `op` `insert`, `update`, `delete` (its `record` null) or `rebaselined`, inserts and updates in the table's order, then deletes in key order. A delete is told only with `deletes: true`, of a table sealed `ok` and not truncated whose survey ran to its end and which holds no keyless and no ambiguous record; a key held with two contents is ambiguous (no row, counted); a record without a key is keyless (counted, never compared). A new `normalize:`, or an earlier table surveyed before `changes:` was set, gives one `rebaselined` row and no other, and the told index starts again. The table's outcome gains `changes` (`recon.domain.documents.ChangeSummary`): the change table, the `previous` table compared, the spec's digest, the rows by op, the keyless and ambiguous counts, and `deletes_withheld`. `record` is the source's content, untrusted. The contract: `docs/reference/changes.md`, which `recon --skill -r changes` prints.
- **A record's content is a keyed BLAKE2b hash** (16 bytes, of its canonical JSON without its volatile fields and recon's own), under the mission's key, `.recon/<mission>/changes.key`, random, mode 0600, made by the first survey that needs it (`MissionStore.change_key`, new). Each table keeps its told index beside it, `<output>.keys.jsonl`: a cache of a pure fold, computed again from the chain when it is missing or stale, and no table. A hash appears in no change row, outcome, warning or telemetry.
- **A stream's window is told against its chain**, the same told index through each window's `previous`; a window never tells a delete. `retain:` removes a window's change table and key index with it.
- **A new warning**, `deletes_withheld`: a table's deletes asked for and not told (truncated, keyless or ambiguous), with the fix for each. The plan reports `changes.key`, `.volatile` and `.deletes` in `provenance`, and refuses a key field `normalize:` does not make, a field starting `_`, `deletes: true` on a stream or on an `offset` or `page` crawl (whose records shift under it when the source loses one: page by link, cursor or header, or `deletes: false`), and an output named as a change table or key index, or whose SQL name a change table would take.
- **A large comparison joins on DuckDB**: past `memory_keys` keys (200,000 by default; `root(memory_keys=)`), the join of a table's keys with its told index runs on a DuckDB connection of its own (`root(key_join=)`, the `KeyJoin` port; `DuckdbJoin(memory_limit="96MB")`) that runs no mission SQL, within its memory limit, spilling to a private temporary directory, with the rows the in-memory join gives.
- **The `ArchiveStore` port gains `read_table`** (a sealed table's records), and its sidecars a `keys` kind; `MissionStore` gains `change_key`.

### Schedules, the mission lock and private files

- **`schedule: {every, missed}`, a new top-level key** (ruling S1): run the mission by the operating system's scheduler (see `recon schedule` below). `every` is required in it and is bare seconds, at least 60 and whole minutes that divide a day (60, 120, ..., 600, ..., 3600, ..., 86400), so the ticks fall on one daily grid every scheduler keeps; another value is a plan problem whose fix names the nearest two. `missed` is `once` (the default: ticks missed while the host was asleep or off run once, coalesced, when it is back) or `skip`. The default is no schedule. A scheduled mission's `deadline:` defaults to 0.8 × `every`, so a tick ends before the next is due; the plan's `provenance` says `schedule.every`, `schedule.missed` and `deadline`, each with its origin.
- **`recon schedule install | list | remove | status`** (ruling S3; `recon.schedule_install`, `schedule_list`, `schedule_remove`, `schedule_status`; `recon.v1.schedule` and `recon.v1.schedules`): a mission's `schedule:` projected onto the operating system's own scheduler, with no recon daemon: launchd's user agents on macOS, systemd's user timers on Linux (`Persistent=true` for `missed: once`), the user's crontab elsewhere (`--platform` chooses; recon edits only its own marked block there, and keeps every other line). Each tick runs `recon schedule tick <mission> --project <dir> --config-sha256 <digest>` by recon's absolute path, in argv form, from the project, with a PATH of absolute directories no other user can write; launchd's and cron's output go to `/dev/null`. The files hold no secret and no `OTEL_EXPORTER_OTLP_HEADERS` (a tick's credentials come from what the mission names, at run time), are written `0600`, and only into the user's own domain. `install` is idempotent (`installed`, `unchanged`, `replaced`), records what it put in place in `.recon/<mission>/schedule.json`, and spreads missions due at once by an offset of `hash(mission) mod every`, whole minutes. `status` says whether each schedule is installed as written, whether its config changed since (a `config_changed` warning: its ticks are refused until it is installed again), and when the next tick is due. Under cron, `missed: once` is a `missed_ignored` warning: cron runs no tick it missed. Two new problem kinds, `config_changed` and `missed_ignored`.
- **`recon schedule tick <mission> --project <dir> --config-sha256 <digest>`** (`recon.schedule_tick`, `recon.v1.tick`): what an installed schedule runs, one tick: a survey under the mission lock, from the project. It refuses a config whose sha256 is not the digest installed (`stale`, a new error kind with its own exit code, 12, until `recon schedule install` again: a schedule makes the config, which runs commands, a persistence vector); a tick while another survey holds the mission exits `busy` (11), skipped, its `details.skips` counting the skips in a row, and the second in a row is an overrun whose fix says to raise `every` or lower `deadline:` (a `schedule_overrun` warning in `status`, a new problem kind); under `missed: skip`, a tick that starts more than 60 s after it was due runs no survey (`skipped_by: missed`). Each tick is a line of `.recon/<mission>/schedule.log` (`scheduled`, `started`, `ended`, `exit`, `kind`, `archive`, `skipped_by`, `late_s`), `0600`, capped at 1 MiB with one rotation (`schedule.log.1`); the archive a tick writes records `scheduled_at` and `late_s` in its `meta.yaml` (a survey by hand has neither). `recon schedule status` adds the `last_tick`, how late the schedule is (`late_s`) and the `skips` in a row. The ruling's log field `skipped` is `skipped_by`, since `skipped` is the plan's sources passed over (one name, one shape), as a window's reason is `closed_by`.
- **A scheduled mission's plan warns `env_unscheduled`** (a new problem kind) for each credential a source it reads names as `env:NAME` (`auth.token`, an `mcp` source's `token` or a stdio server's `env` values), at the reference's path, whether or not the variable is set where the plan runs: a tick runs in the scheduler's environment, never the user's shell's, so the variable is unset on every tick. The fix names `auth.token: file:PATH` (a file only you can read, mode 0600) or `auth.headers_helper`, then `recon schedule install` again. The schedules reference now says how an `api` source's tick gets its credential.
- **A scheduled mission's plan warns `package_unpinned`** (a new problem kind; ruling A1's last clause) for each package a stdio MCP server or a `cli` command has `npx` or `uvx` fetch without an exact version (`npx -y pkg`, `pkg@latest`, `uvx pkg`, `uvx --from 'pkg>=1'`), at `catalog.<i>` or `collectors.<i>`, `got` the package: each tick would run whatever was published last. The fix is the pinned form, `pkg@<version>` or `pkg==<version>`, then `recon schedule install` again. The commands judged are what each run's type describes (`server`, `commands`), so a collector type of your own that describes its commands so is judged too.
- **One survey of a mission at a time** (ruling S2): a survey holds the mission's `writer.lock` (`.recon/<mission>/writer.lock`, an `flock` holding its pid, as a stream's does) from before it writes anything until it returns, so a second survey of the mission, by hand or a scheduled tick, is refused `busy` (11), its `details` naming the `mission` and the holder's `pid` and its fix how to stop it. Only a stream refused a second writer before; two overlapping surveys each wrote an archive from the same sources. A dry run holds nothing. `busy`'s meaning and next step now cover a survey too. The `ArchiveStore` port gains `hold_mission` and `release_mission`.
- **What recon writes for a mission is private** (ruling A2): each directory it makes under `.recon/` is `0700` and each file `0600` (the config, tables, `meta.yaml`, the event and capture logs, capture bodies, locks, tombstones, a table's page log and told index, the change key), set as each is made, whatever the umask. They were `0755` and `0644` under the usual umask. A directory or file made before keeps its mode; `recon status` warns `mission_exposed` (a new problem kind) for a mission one of whose paths other users can reach, with the fix `chmod -R go-rwx '<mission>'`, and changes nothing. The `MissionStore` port gains `exposed(name)`.
### Fixed: the round-4 review

- **Every change row a reader can see is folded, so none is told twice** (F3): a survey stopped, or one that died, while comparing its tables left change tables a reader could read and the next survey told again. Now each table's told index is written first, then its summary into `meta.yaml` (written as each table is compared, `ended: null` until the survey says how it ended, which a reader reads as `crashed` if it never does), then its change table; and a table compared is folded however its survey then ended. A store that cannot write a table's told index leaves no change table (`changes.error`, kind `store`, and `archive_unfinished`).
- **A stranger's text never stops change detection** (F6): a lone surrogate in a record (JSON `"\ud800"`, which a mail subject can carry) raised in the hash, and on DuckDB in the join's files, leaving every tick's archive unfinished. It is hashed as its code point's bytes, and a key goes to DuckDB as the hex of its bytes. Anything else that fails in the change phase is now a classified failure of that table's changes, never of its survey or window: the outcome's `changes.error` (`kind`, `message`, `fix`), no change table, no told index, and a `changes_failed` warning (a new problem kind); the next table of its output tells its changes too.
- **A told index edited by hand is not trusted** (F5): its header carries `mac`, a digest of the header and every line keyed with the mission's key, checked on read; one that does not hold is computed again from the chain. An index whose counts were made to agree was read as told, and could tell the delete of a key no table ever held.
- **A told index computed again folds each table as it was told** (F2): each table's change outcome records `deletes_told`, whether its deletes were told, and a rebuilt told index uses that, never the `deletes:` the mission says now. Switching `deletes:` on, then losing a kept index, dropped a key no delete row had told, so its delete was never told.

## 0.13.0 — 2026-10-24

### Changed (breaking)

- **An archive's `state` is `writing`, `complete` or `incomplete`**, in `status`, `query`, `read_since` and a survey's own `status`: `ok` is now `complete` (a state, where a table's `ok` or `error` stays its outcome), and `writing` is new. `status` and `query` said `incomplete` for an archive being written. Each document with a `state` also has `ended`: `finished` (the survey ran to its end, so an `incomplete` archive's tables failed), `stopped` (it was stopped on request: Ctrl-C, SIGTERM, a stream's stop), `crashed` (it left no `meta.yaml`: killed, or it could not write one), or null while `writing`. `meta.yaml` gains `ended`, `finished` or `stopped`, written by the survey or window; `crashed` is never written, read from a missing `meta.yaml`. A survey stopped on request now writes its `meta.yaml`, with the tables that ended before the stop, then exits `interrupted` (130) as before. The survey holds an `flock` on `writer.lock` in the archive while it writes and removes it when done, so `incomplete` now means the survey failed a table, was stopped or died, never that it is still running. An archive is made whole (its lock and marker in place) under a hidden name and renamed into place, so one is never seen half made; a survey whose archive id is already taken, or taken by another survey while this one makes it, is refused (`store`) rather than written into the existing archive. A survey killed while making its archive leaves a hidden `.<archive id>.<pid>.making` directory; `recon status` reports each whose survey is gone as an `archive_abandoned` warning (a new problem kind, in a new `warnings` list on `recon.v1.status`) with the command that removes it, and removes nothing. A survey's own `status` stays `ok` or `incomplete`.
- **The `ArchiveStore` port** (what `root(archives=...)` takes) has `state(archive)` (`writing`, `complete` or `incomplete`) and `release(archive)` in place of `is_incomplete(archive)`, and `read_since(archive, cursor, *, max_records, max_bytes)`; its `tables()` lists a table not yet sealed, with `StoredTable.sealed` false.
- **Stopped on request is `stopped` everywhere; a writer that died is `crashed`.** A window a stop sealed says `closed_by: stopped`, not `signal` (a library `StreamStop` is no signal), and an archive whose writer died says `ended: crashed`, not `stopped`, which now means a stop on request alone. Renamed before 1.0, with no alias. The exit kind of a stopped command stays `interrupted` (130), the kind every gnx tool shares.
- **The skill says what `--json` prints as it is**: one document, but `recon watch --json` one a line, a read each, where it said every command prints one.
- **`recon stream` names its stream with `--stream` alone**: the `--collector` alias is gone, so the stream has the one name `watch` and `query` give it. Removed before 1.0.
- **The rest of the names with two shapes have one**: `recon.stream(name, stream)` names its stream as `read_since`, `watch`, `query` and `plan` do (`stream=`, where it was `collector`); `recon.v1.stream`'s last window, a window outcome, is `last_window`, so `first` and `last` are always ids or the ends of a span; a provenance entry's `source` is `origin`, so `source` is always a catalog source's name; a read's retired windows are `retired_range`, so `skipped` is always the sources a plan passed over; the plan's `writes.streams` is `writes.stream_paths`, and **`writes.captures` (released in 0.12) is `writes.preserve_raw`**, so `streams` lists stream statuses and `captures` is a count. The capture line, `recon.v1.capture`, keeps its names: other tools write it, under its own schema. Renamed before 1.0, with no alias.
- **A read's caps are `max_records` and `max_bytes`**: `recon.read_since`, `recon.watch` and the `ArchiveStore` port's `read_since` take `max_records` where they took `limit`, so both caps of a read are named alike (`READ_LIMIT` is `READ_MAX_RECORDS`). Renamed before 1.0, with no alias. The caps of `window:` and `buffer:` stay `{records, bytes}`, since the object they are in names them.
- **One field name, one shape, in every document.** `archive` is always an archive's id, what `--archive` takes, and a directory is `path`: `recon.v1.survey`'s `archive` (its directory before) is the id, beside a new `path`; `recon.v1.query-rows` and `recon.v1.records-since` drop `archive_id` for `archive`, and their directory is `path`; a window outcome's directory is `path`, not `archive`; the plan's `writes.archive` is `writes.archive_path`; an error's `details.archive` is the id, beside `details.path` (a failed survey, a taken archive id, a table layout recon cannot read; a failed stream's is its window's id). `records` and `windows` are counts, as in `meta.yaml`: `recon.v1.records-since`'s list of records is `table_records`, `recon.v1.survey`'s list of windows `stream_windows`, and `recon.v1.query-rows`' range of windows `window_range`. Renamed before 1.0, with no alias; `docs/reference/live-reading.md` states the rule.
- **A read's tables read to their end are `exhausted`, not `sealed`** (`recon.v1.records-since`, and the `NewRecords` the `ArchiveStore` port's `read_since` returns): `sealed` keeps one meaning, a table's own state, renamed into place by its writer (`StoredTable.sealed`). A table is exhausted for a reader once it is sealed and the reader has read all of it. Renamed before 1.0, with no alias.
- **`stream_overflow` is `records_dropped`, and `many_windows` is `windows_many`**: a problem kind names its subject, then its state, as `env_unset`, `events_dropped` and `source_stuck` do. `records_dropped` is now one warning for each cause (a full buffer, a record too large, a stop at once), each at the path of its own key with its own fix, where `stream_overflow` was one warning that named every knob. Renamed before 1.0, with no alias.
- **A window closed by its time bound says `closed_by: seconds`**, not `window`: each bound of `window:` is named by its key, as `records` and `bytes` already were (in `meta.yaml`'s `stream.closed_by`, a window outcome's `closed_by` and the `window` event). Renamed before 1.0, with no alias.
- **The `ArchiveStore` port keeps streams too**: `create(..., stream=)` and `archives(..., stream=)` make and list a stream's windows; `hold_stream`, `release_stream`, `stream_state`, `streams`, `last_record`, `size`, `retire` and `retired` are new; `write_table` takes `keep_on_error`. `ArchiveQuery` gains `execute_across(archives, sql)`, and `CaptureLog` gains `tee(collector, data)`. A store, query or capture log of your own given to `root()` implements them.
- **The `TelemetryFactory` a `Recon` is built with** takes the survey's channel as a second argument, None for an operation with none.

### Added

- **Streams: sources that do not end, collected into windows.** A collector entry with `window: {seconds?, records?, bytes?}` (`seconds` at least 1), or of a type whose records do not end, is a stream: its records go into windows, each window an ordinary archive (its `meta.yaml`, one table, its state, its query) sealed when the first of its bounds is reached (a time window is half-open, timed on the clock port) and chained to the one before by `meta.yaml`'s `stream` (`name`, `index`, `previous`, `opened_at`, `closed_at`, `closed_by`, `window`, `sources` with each source's `first` and `last` position, `records`, `dropped`, `gaps` and `arrivals`, and `reproducible`). A window that ends is sealed `ok`, `closed_by` `seconds`, `records`, `bytes`, `eof`, `stopped` or `until`; one whose source failed is sealed `error` and keeps the records it got. Windows live in `.recon/<mission>/streams/<stream>/`, one writer a stream at a time, so a window's id (its index, then when it opened) is unique by construction. The contract: `docs/reference/streaming.md`, which `recon --skill -r streaming` prints.
- **`recon stream <mission> --stream NAME`** (`recon.stream(...)`, `recon.v1.stream`, `recon.stream_failure`) rolls a stream's windows in one process. It runs **one window by default**, so it returns unless told otherwise; `--windows N`, `--until TIME` and `--forever` extend it. Ctrl-C or SIGTERM seals the window being written (`stopped`) once what waits is written, and returns (exit 0); a second seals it at once, what waits counted dropped. The command asks a `recon.StreamStop` from its signal handlers, so the first stop drains however busy the writer is; `recon.stream(..., stop=)` takes one. A later run resumes after the last window, its source after the position of the last record kept (each record carries it as `_position`, in the same line): exactly once for a source with positions; every restart is recorded as a gap, `resumed` when the source was asked to go on from a position. A window its writer died in reads `incomplete` and is never changed, its torn last line moved aside to `.torn`. It says when it will return as it starts, and `--dry-run` says it in `provenance` (`stream.returns`, seconds, or null for `--forever`). `--forever` with a bound, `--windows` below 1 and an `--until` that has passed are `usage` errors with a fix; a second writer of a stream is `busy`, a new error kind with its own exit code (11).
- **`recon survey` runs one window of each stream entry**, in turn, after the snapshot tables, in the survey document's new `stream_windows` (`recon.WindowOutcome`); a failed window makes the survey `incomplete`. Its dry run says when it returns at the latest, `survey.returns` in `provenance`: the mission's `deadline:` plus each stream's window `seconds`, or null with a note of what is unbounded.
- **A stream's run says when it returns under `--json` too**: `recon.v1.stream` carries `returns_s` and `returns`, the notice the run gives on stderr and to `on_event` as it starts, which a `--json` caller did not get. `recon stream --help`, `recon survey --help` and the skill say a window of the default 300 s can outlast a tool call, and to read `stream.returns` from `--dry-run` first.
- **`buffer: {records, bytes, max_record_bytes, overflow}`**: the bounded buffer between a stream's source (read on a thread of its own) and its windows, 10000 records and 16 MiB by default; `overflow` `block`, `drop_newest` or `drop_oldest`, by default `block` for a type recon reads at its own pace and `drop_newest` for one whose source sends regardless (`CollectorType.paced_by`). A record over `max_record_bytes` (1 MiB) is dropped. Every drop is counted in its window's `meta.yaml`, its `recon.collect` events (`recon.dropped`) and a `records_dropped` warning, a new problem kind, one for each cause at the path of the key that governs it (`buffer` for a full buffer, `buffer.max_record_bytes` for a record too large, the entry for what a stop at once dropped), its count in `got`.
- **`retain: all | {windows?, seconds?, bytes?}`**, default `all`: a rule removes a stream's oldest sealed windows it does not keep, leaving a tombstone for each, a line of the stream's `retired.jsonl`; the newest window and one never sealed are always kept. A stream that keeps every window by default is a `retain_unset` warning in the plan, with the growth and a fix.
- **The plan says every default it fills in**: `recon.v1.plan` gains `provenance`, each stream setting's `{path, value, origin, note}` (`origin` `mission`, `type` or `recon`), and `writes.stream_paths`; a stream's run carries `stream`. A window with no bound, `buffer:` or `retain:` on an entry that is no stream, a stream that would run against more than one source, `deadline:` on a stream, a `normalize:` column named `_position`, and `max_record_bytes` above `buffer.bytes` are plan problems with a fix.
- **The `tail` collector type**: a `file` source (a new kind; a relative `url` is the project root's) followed as it grows, each line a record positioned by inode and offset, through rotation and truncation; `start: end | beginning`, `interval: 1`.
- **The `sse` collector type**: server-sent events from an `api` source's `endpoint`, each event a record `{id, event, data}` positioned by its id; a dropped connection reconnects with `Last-Event-ID` after a full-jitter wait (unseeded, so processes do not reconnect in step, and cut short by a stop), within `reconnect: 5` failed connects in a row (a quiet connection that times out spends none), and is recorded as a gap. An event whose data, or any one line, passes `max_record_bytes` is dropped and counted, the line let go as it arrives rather than held up to the source's `max_bytes`; `CollectorContext.gaps` gains `drop()` for a plugin type that drops a record. It reads the body as it arrives through the requester's new `follow()`, on httpx2, which recon already depends on.
- **`--stream` on `recon watch` and `recon query`** (`stream=` on `recon.watch`, `recon.read_since` and `recon.query`): a watch follows a stream from its latest window (or `--archive`'s) into each window after it; a query reads every window as one, each table the union of its windows', `--since` and `--until` choosing windows from their ids alone, refusing windows collected under different configs with the ranges to narrow to. A watch whose cursor's window was retired goes on from the next window kept, and that read's `retired_range`, `{first, last, count}`, names the windows it jumped. The query's `window_range` is the range it read, `{first, last, count}`, and past 300 windows it warns `windows_many` (a new problem kind) with how to narrow it. `recon status` lists each mission's `streams` with their state, windows and retired windows.
- **A collector type of your own may be a stream**: `CollectorType` gains `unbounded` and `paced_by`, declared through the same entry point the built-ins use, and `CollectorContext` gains `clock` and `gaps`. A type whose records carry `_position` takes `after` in `collect`. `docs/reference/extending.md` says what such a type must do.
- **A capture of kind `stream`**: with `preserve_raw`, each window keeps one, each record as its collector gave it with its order and its offset from the window's open, from which the window replays to the same table.
- **`busy`, a new error kind (exit 11)**: another recon is writing the stream. `conflict` keeps its one meaning, a config that would be overwritten. The writer keeps its pid in the stream's `writer.lock`, so `busy` names it in `details.pid` and in its fix, `kill -TERM <pid>`, which seals the window it is writing.
- `source_stuck`, a new warning kind: a stream's source that had not returned its next record when the stream stopped. Its `got` is the collector type, and its fix says whose the type is: for recon's own (`tail`, `sse`), a bug to report in recon; for a third party's, the package that registered it (`Plugins.collector_packages`, new: each collector type's distribution, as its entry point was installed).
- **`recon watch <mission>`** follows an archive as a survey writes it: each record as a JSON line, or under `--json` each read as a `recon.v1.records-since` line, and returns when the archive is no longer being written and all of it is printed (at once for a finished archive). `--once` reads once; `--interval` sets the seconds between reads (1 by default); `--cursor` reads on from an earlier read; `--max-bytes` bounds a read's bytes (1 MiB by default); `--archive` names an archive other than the latest. A cursor recon did not give, or an interval of 0 or less, exits 2 with a fix. `recon.watch(...)` is the same in a program. Its contract: `docs/reference/live-reading.md`, which `recon --skill -r live-reading` prints for an agent; a walk-through: `docs/how-to/watch-a-survey.md`.
- **`recon.read_since(mission, cursor=None, *, archive=None, max_records=1000, max_bytes=1048576)`** follows an archive while a survey writes it. It returns `recon.v1.records-since`: the whole records written since the cursor, from sealed tables and the one being written, at most `max_records` of them and `max_bytes` of their bytes, cut at a whole record and at least one, with `more` when a bound cut it; the archive's `state`; the tables `exhausted` (sealed, and read to their end) and `retracted` since, each told once; and the opaque `cursor` to read on from. A cursor recon did not give for that archive, or a `max_records` or `max_bytes` below 1, is a `usage` error with a fix.

### Changed

- **recon is no longer only a snapshot collector**: the documented non-goal "Not a stream processor" is reversed (owner ruling 2026-10-24); a source that does not end is collected as a stream. recon still pushes nothing to subscribers: a reader follows the archives.
- **A problem under a union field has a plain path**: pydantic's member labels (`literal['all']`, `RetainSpec`) are left out of `path`, and a value gets only the errors of the shape it has.
- **The skill points to streams in one line**, the rest in `recon --skill -r streaming`, one text with `docs/reference/streaming.md`.
- **The skill and `recon --skill -r live-reading` teach an agent to poll**: `recon watch --once --json`, then the next read with `--cursor`, since a watch holds its command while the writer runs and one of a `--forever` stream never returns. The skill's telemetry and capture paragraphs point to their references for what those already hold.
- **The hook that captures MCP results moved from the skill to `recon --skill -r config-patterns`** (MCP Results Captured by a Hook), so the skill keeps within its budget; the skill points there.
- **The skill teaches telemetry through `recon --skill -r telemetry`**, one text with `docs/reference/telemetry.md`, so the skill stays within its budget.
- **No receiver slows a survey.** OpenTelemetry's sink and the `on_event` callback receive a survey's events through a bounded queue (`ThreadChannel(queue=4096, drain_s=10.0)`, `root(channel=)`) that a thread drains, so a slow one neither slows the writing of the archive nor changes it. An event the queue cannot hold, or that the survey's end could not wait for, is dropped and counted in an `events_dropped` warning, a new problem kind. **An `on_event` that raises no longer fails the survey**: it gets nothing more, and is a `telemetry_failed` warning. A receiver that never returns from an event cannot hold the survey past the drain time: it is named in a `telemetry_stuck` warning, a new problem kind, and is not closed. `on_event` is called on that thread, not the survey's, and every call is made before `survey` returns.
- **A table's progress is in its telemetry.** While a table is written, its `recon.collect` span has a `recon.collect.progress` event at most once a second (`Survey(progress_s=)`, 1.0 by default, timed by the clock port), carrying `recon.records`, the records written so far: a line in the archive's `telemetry.jsonl`, and a span event in OpenTelemetry.
- **The event log opens its file once per survey**, not once per event, writes each event in one write as it happens, and closes it when the survey ends (`Telemetry.close()`).
- **`query` reads only sealed tables.** A query of an archive being written sees the tables finished so far; the one being written is not a table yet, and the human output warns that the archive is being written.
- **A table being written is readable as it goes.** Its records reach the table's file as whole lines at most 64 KiB or 250 ms after the collector gives them, never part of a line, where they were buffered and reached it every 1000 records. Flushing to the disk stays every 1000 records. `scripts/bench_table_write.py` measures the cost against the old writer, median of 9 with a warmup and the order rotated: within 2.1% on 200,000-line `cli` surveys and on the writer alone, for mixed and for short lines, against 82-204% for a write per line. `ArchiveFiles(flush_bytes=, flush_s=)` sets other bounds.

## 0.12.0 — 2026-10-22

### Removed (breaking)

- **No extras.** The `otel` extra is gone: the OpenTelemetry SDK and its OTLP exporter are installed with recon, so the `OTEL_*` variables are enough to export, with nothing else to install. The library still installs no provider: a program that imports recon configures OpenTelemetry itself, or calls `recon.configure_telemetry()`. The `dev` extra is gone too; recon's test tools are not part of an install.
- **No OTLP over gRPC** (owner ruling 2026-10-22). `OTEL_EXPORTER_OTLP_PROTOCOL=grpc`, or a signal's own `_PROTOCOL` variable set to it, is refused with an `otel_unavailable` warning naming what to set, and the signals it governs are not exported, rather than sent as http/protobuf to an endpoint that speaks gRPC. recon depends on `opentelemetry-exporter-otlp-proto-http` in place of `opentelemetry-exporter-otlp`, which brought the gRPC exporter and `grpcio`.

### Changed (breaking)

- **HTTP goes through httpx2**, Pydantic's maintained continuation of httpx, in place of httpx. Redirects, timeouts and the credential rule for a redirect behave as they did. TLS is verified against the operating system's trust store (httpx2's default, through `truststore`) rather than certifi's bundle. A request span's `error.type` for a client exception is `httpx2.<class>` (`httpx2.ConnectError`).
- **An `api` collector's `params:` are the query string only; `vars:` fill the `{placeholders}`** in `endpoint:` and `body:` and are sent nowhere else. `params:` used to do both, so a value meant for a path or a POST body (a search topic, a target URL) also went out as a query parameter, into the server's access log. A mission that filled placeholders from `params:` moves those entries to `vars:` (the `github-audit` template and the skill's patterns do); the plan names each placeholder left unfilled.
- **A collector type declares the keys it takes** (`CollectorType.settings`, a schema the plan validates them by, each problem at its path), so a plugin type can take settings of its own without an edit to recon. The built-ins declare theirs, so a key one type takes is a plan problem on another (`run:` on an `api` collector was accepted and ignored), and `extract:` is for a type that reads a body (`api`, `capture`). An unknown key on a collector of a type that is not installed is left unjudged, and the plan says it is incomplete. **Breaking for a plugin type** that read keys from its entry without declaring them: with no `settings` schema, every key beyond the shared ones is now a plan problem (`unknown_key`), so such a type must declare `settings` to keep working.
- **A collector pinned to a source of a kind its type cannot use is a plan problem.** `cli` pinned to a `web` source ran in recon's working directory and surveyed `ok`; `mcp` pinned to an `api` source used the API's URL as an MCP server's; `api` or `web` pinned to a `local` or `mcp` source failed only at survey time. A collector type now declares the kinds it accepts (`CollectorType.accepts_kinds`; `None`, the default, takes any): `cli` takes `local`, `api` and `web` take `api` or `web`, `mcp` takes `mcp`, `capture` any. A mission that pinned such a pair no longer plans.
- **A collector with no `source:` runs against the catalog sources of kinds its type accepts, and no others** (owner ruling 2026-10-22). It ran against every catalog source, so adding a `web` source to a mission ran each unpinned `cli` command again in recon's working directory, gave the `cli` type the variables of every `api` source's `auth.env`, and asked a directory for a web page. The plan document's new `skipped` lists each source a collector passed over (`{collector, source, kind}`), and the dry run's text says so per collector; a catalog with no source of a kind the type accepts is a plan problem (`missing_key` at `collectors.<i>.source`). The `fan_out_mixed` warning, which said such a collector would run against them all, is gone. A table such a run used to write (`<collector>-<source>` for a source of another kind) is no longer written. A type whose `accepts_kinds` is `None` (`capture`, and a plugin that does not declare it) fans out as before.
- **A survey's requester is built over the survey's rate limiter**: `root(requester=...)`'s factory takes it as a third argument, after the telemetry and the deadline.
- **`{{` and `}}` write a literal brace where recon fills placeholders** (an `api` endpoint, body and params, a `web` endpoint, an `mcp` collector's arguments and resource), as in Python's format strings. A compact GraphQL body, `{"query": "{viewer{login}}"}`, was refused as `unresolved {login}` with no way to write it; it is now `{viewer{{login}}}`. A `cli` command's braces stay its own (`--format '{{.Name}}'` is passed as written). A `{{` that meant a brace around a filled placeholder now writes a literal brace instead: `{{{name}}}` is a brace, the value and a brace, where `{{name}}` was, and `{{name}}` is the text `{name}`, sent with no plan warning.

### Changed

- **Telemetry names are not contract** (owner ruling 2026-10-22): a span's, a metric's or an event's name and an attribute's key may change without notice. What telemetry never carries (a credential in a URL, a failed span's error text, an MCP call's arguments or result) is.
- **`meta.yaml` names the layout of the archive's tables** (`table_layout: 1`), as it names its own format, and `query` refuses an archive in a layout it does not know rather than misreading it. An archive with no `table_layout` is in layout 1.
- **A collector type is built only for a survey that uses it**, so one plugin's broken factory no longer warns in every survey. A table of a type whose factory raised fails as `config`, naming the type.
- **`CollectorContext` carries `shell`**, the port the `cli` type runs commands through, and a transform that reads files declares it by taking a keyword-only `roots` (recon binds the mission's directories to every transform that does; `$markitdown` is no longer special-cased by identity).
- **A missing source is a plan problem only.** The survey no longer records a pinned source missing from the catalog as a failed table: the plan refuses the mission first, so no archive is made.
- **Source kinds are open.** A collector type may add the kinds of catalog source it needs (`CollectorType.source_kinds`); a source of a kind nothing installed adds is a plan problem naming the installed kinds, where it was a model error.
- **`CollectorContext` carries the survey's `telemetry`**, so a plugin type that does its own I/O opens spans that nest under its table's.
- **A survey's collectors and requester are closed when it ends**, however it ends. One collector serves every table of its type, so it may hold a session across them (a stdio server); recon calls its optional `close()` once. The requester keeps one HTTP session per survey (connections are reused between requests; no cookie carries over) and closes it.
- **`ArchiveStore.tables()` describes each table of an archive** (its output name, its file, whether it is empty and the columns it keeps), and the query engine reads only what it lists, so how an archive is stored is known to the store alone.

### Added

- **An `mcp` collector type: recon calls an MCP server's tools and reads its resources itself.** An `mcp` source names a stdio server recon starts (`command:`, `args:`, `env:`), or a remote one (`url:`, with `token:` or `headers_helper:`); credentials are references (`env:NAME`, `file:PATH`), never written. An `mcp` collector names a `tool:` with its `arguments:`, or a `resource:`; `vars:` fill their placeholders, and `extract:` and `normalize:` apply as for `api`. Records come from a tool's structured content when it declares an output schema, else from the JSON in its text (`result: structured | text` says which). A tool error fails the table, text that is not JSON fails it, and an answer with no content keeps it empty with a `result_empty` warning. One stdio server serves every table of a survey, runs in the project root (`CollectorContext.project_dir` gives a plugin type that directory), and is stopped when it ends; every call draws from the source's `rate_limit` and is one `recon.mcp.call` span carrying no arguments and no result; with `preserve_raw`, each answer is an `mcp` capture with the source's credentials redacted, in the result and the request: one of 8 characters or more wherever it appears, a shorter one only where it is a whole value (a JSON string, a header's, a query parameter's), never in a number, a boolean or longer text, so the capture stays JSON (a `headers_helper`'s header is a credential by its name: `Authorization`, `X-Api-Key`, or a name holding `key`, `token`, `auth`, `secret`, `cookie`, `session`, `signature`, `password` or `credential`; a bearer token is redacted on its own too, and so is each cookie's value). A server behind an OAuth sign-in in a browser stays on the hook route (`recon capture`). The client is FastMCP's (`fastmcp-slim[client]`), a dependency of every install, loaded only when a survey or a dry run reaches a server. The template `mcp-server` and the how-to `docs/how-to/collect-from-an-mcp-server.md` show one.
- **A dry run checks what a run needs of the host, for a type that says so.** A collector type with a `preflight` has its collector built by the dry run and asked `requirements(entry, source)` for each run; the plan lists each requirement with whether it holds (`requirements`, with `need`, `holds`, `why`, `fix`, `needed_by`), `runnable`, and what the dry run did (`preflight`). For `mcp`, the dry run starts each stdio server (and connects to each remote one), lists its tools and resources, checks each run's tool and arguments (against the tool's input schema) or resource, and stops it. A tool's input schema is checked first, its `$ref`s resolved within it alone, so one that is not valid JSON Schema is a requirement that does not hold rather than a crash. The plan stays valid when a requirement does not hold; the survey fails that table as `config`.
- **A source kind can take settings of its own.** A collector type that adds a kind may declare their schema (`CollectorType.source_settings`), what the kind needs of the shared keys (`check_source`), and the variables it reads (`source_env`), which the mission then declares for the types that use the source, and the plan warns about when unset. A source of a kind with no settings of its own still needs `url:`.
- **An archive records where its inputs came from.** `meta.yaml` gains `resolved`: `root`, how the project root was found (`argument`, `repository`, `working_directory`), and `env`, each variable the mission declares, `set` or `unset`, never its value.
- **`CollectorContext.rate_limiter`**, the survey's one bucket per source, which the requester draws from too: a type that reaches a source another way draws a token per call.
- **A survey and each table can be bounded in time.** `deadline:` at the top of a mission bounds the whole survey, and `deadline:` on a collector each of its tables, in seconds. Requests, waits for the rate limit or a retry, and commands are cut to what is left; a table cut short, and every table not started by the survey's deadline, fails as `transient` with a fix naming the `deadline:` to raise. A `deadline:` is a finite number of seconds, or the plan has a problem. Exit 5's next step tells them apart: if a table's error names a `deadline:` or a source's `timeout:`, raise it, since such a table fails the same way on every retry; else (a 429, a 5xx, a network error) survey again later. `CollectorContext.deadline` gives a plugin type the same bound.

### Fixed

- **A redirect chain is held to the `timeout` and the deadline, and each hop draws a rate-limit token.** Every hop was sent with the whole per-phase timeout and the budget was checked only while reading the body, so seven redirects of 0.8 s each under `timeout: 1` took 20.1 s; only a send's first hop drew a token. Each hop is now checked against what is left of its send and the deadline, and sent with only that as its timeout: the same chain fails as `transient` in 6.0 s.
- **A source's `timeout` bounds each send in wall time.** It was httpx's per-phase timeout, so a server that sent its body a byte at a time within it held the table, and every table after it, for as long as it liked: a source with `timeout: 2` sending a 40-byte body one byte every 0.5 s took 19.9 s and succeeded. The body is now read against the timeout, chunk by chunk; the same request fails as `transient` in 9.2 s (three sends of 2 s and the backoff between them), and in 5.2 s under a table `deadline: 5`.
- **The hook route's `tool_input` is documented as kept whole.** The capture log's docs said a credential never reaches it, which held only for what recon fetches itself: a `PostToolUse` payload's `tool_input` is stored as given, so a key an MCP tool takes as an argument is in the log. SECURITY.md (boundary 5) and the capture format now say so; recon does not guess at which arguments are keys.
- **Audio is never sent to a speech service.** markitdown's audio converter uploaded a recording to Google's speech API, so a `web` collector that fetched audio, and `$markitdown` on a local `.wav` or `.mp3` (or one in a ZIP), sent it to a third party outside the requester, its rate limit, spans and capture log. recon now builds markitdown with a named list of converters audited for what they reach (SECURITY boundary 3 lists it); audio, YouTube transcripts, Azure Document Intelligence, markitdown plugins and exiftool are left out. Audio is not converted: it fails its table, naming the document (SECURITY R-14).
- **A `web` collector's YouTube page fetches nothing more.** markitdown asked YouTube for the video's transcript itself, outside the requester (its rate limit, `max_bytes`, spans and capture log), and printed its failures on stdout, where `--json` writes the document. The page now converts from the bytes the requester fetched, as HTML; the transcript is not collected (SECURITY R-12).
- **`$markitdown` reads a relative path where the command that printed it ran.** A path a `cli` command printed (`rg --files`, `find .`) is relative to its `local` source's directory, but was resolved against recon's working directory, so it named another file or none and was refused. A transform may take a keyword-only `base`, which a `cli` collector binds to the directory its command ran in.
- **A fetched document is converted by the content type its server gave.** The converter ignored it and let markitdown guess from the bytes, so a `text/plain` reply that looked like CSV became a table. It also builds markitdown once per survey rather than once per document.
- **recon's spans are current while its work runs, and requests carry their trace context.** recon built its OpenTelemetry spans from events and never made one current, so a span another library opened during a table (an instrumented HTTP client, a plugin's own) landed under the caller's span or in a trace of its own; and no request carried `traceparent`, so a server's spans could not join. A sink may now have an optional `around(event)`, entered for the work of each span (the OpenTelemetry sink makes its span current there), and `trace_headers(span)`, which the requester sends with each attempt.
- **An event-log line can be found in the exported trace.** The event log counts span ids from 1 and OpenTelemetry's are random, with nothing tying them; each exported span now carries `recon.event.span`, its event-log id.
- **A dropped sink no longer loses the spans it held open.** A sink that raised was dropped with its OpenTelemetry spans started and never ended, so they were never exported. A sink may have an optional `close()`, called when it is dropped; the OpenTelemetry sink ends its open spans as failed there.
- **Telemetry is exported signal by signal.** Any export variable installed both providers, so a traces endpoint alone also sent metrics to the default endpoint, which logged failures; and only the tracer provider was checked, so a program that installed its own tracer provider got no metrics from recon, and one with its own meter provider had recon try to replace it. A signal is now exported when the shared endpoint, its own endpoint or its exporter asks for it, and only when the program has installed no provider for it.
- **An output name must start with a letter, a digit or `_`.** `name: ""` planned valid and wrote `.jsonl`, a hidden file no query lists, with no warning; `.x` and `-x` were accepted too.
- **A rate limit or timeout that cannot be kept is a plan problem.** `rate_limit: {rps: 0}` divided by zero on the fourth request and failed the table as `unknown`; `burst: 0` waited forever for a token; a timeout of 0 or less was accepted. `rps` and `timeout` must be finite and above 0 (`timeout: .inf` planned valid, then failed every request with an `OverflowError`), and `burst` at least 1. A `timeout`, and an empty bucket's wait for a token (`1 / rps`), must also be a wait the platform's timers take (Python's `threading.TIMEOUT_MAX`): `timeout: 1e12` and `rps: 1e-300` planned valid and then failed every request with the same `OverflowError`.
- **A retry draws a rate-limit token, and its wait is on recon's clock.** The token was drawn once per request, before its retries, so a source answering 5xx was sent to three times for one token; the backoff slept on the real clock, out of reach of a test clock and of any bound recon sets.
- **A failed span quotes nothing from its error.** Its status message was the error's first line, which for a failed `cli` command is the command and for a failed request is its URL, user information included; both went to the OTLP endpoint and the event log. The message is now recon's description of the failure (`the table failed (run_failed); its error is in the archive's meta.yaml`, `HTTP 503`, the exception class), and the error stays in `meta.yaml`. A URL in an error message has its user information and `auth.param` `REDACTED`, as `url.full` has.
- **recon installed on its own can query a timestamp.** DuckDB imports `pytz` to return a TIMESTAMP WITH TIME ZONE (a `::TIMESTAMPTZ` cast, `now()`), and recon did not declare it, so only the workspace's dev group supplied it: installed alone, such a query failed as `unknown`, "report this as a bug". recon now depends on `pytz`, and a module DuckDB cannot import for a result is a `query` error whose fix names it and the cast that needs none. `duckdb` is bounded below 2.0, whose behaviour the skill and the tests do not describe.
- **A UTC time reads as UTC in a query, whatever the machine's zone.** DuckDB reads `2026-03-15T18:42:31Z` as a timestamp with no zone, and a `::TIMESTAMPTZ` cast took the machine's zone for it, so on a machine in Chicago 18:42Z came back as 18:42-05:00, five hours off and nothing to say so. A query's session is now in UTC; a time written with an explicit offset (`+02:00`) still means that instant. The zone is the session's for every query, so `now()`, `current_date`, `date_trunc` and `strftime` on a `TIMESTAMPTZ` give UTC times and days where they gave the machine's.
- **`recon query` reads nothing outside the mission's archives, DuckDB's spill directory included.** DuckDB adds its temp directory (`.tmp/` under the working directory) to the directories SQL may read, so a query could read any file there. A query no longer spills to disk; one that needs more memory than DuckDB has fails as a `query` error that says so (SECURITY R-15).
- **`recon query` runs SELECT statements only.** Its confinement let SQL write wherever it may read, so `COPY ... TO`, `ATTACH` and `EXPORT` wrote into the mission's archives, `meta.yaml` included. Any statement DuckDB does not type as SELECT is now a `query` error (exit 10) whose `details.statements` names it; `WITH`, `FROM`, `DESCRIBE` and `SUMMARIZE` still run.
- **A source's `auth.header` no longer follows a redirect to another origin.** httpx2, like httpx, drops only `Authorization` there, so a key in `x-api-key` went to whatever host the API redirected to. The header now goes only to the origin of the request the collector built, or its upgrade to https; the redirect is still followed, without the key.
- **Two outputs that would be one table are a plan problem** (`name_taken`). The plan compared names exactly, so `a-b` and `a_b`, which SQL knows as one view (every character but a letter, digit or `_` becomes `_`), planned valid and a query of one returned the other's rows; `Foo` and `foo`, one view to SQL and one file on macOS, planned valid and the second table overwrote the first while the survey said ok. The reserved names `captures` and `telemetry` are compared ignoring case too. An output name holding `/`, `\` or `..` is a plan problem (`invalid_value`): `bad/name` failed its table as `unknown`, and `../x` wrote outside the archive. The skill states the view-name rule as the code applies it.
- **A survey whose archive could not be finished reports it.** When `meta.yaml` could not be written or the archive marked complete (a full disk), the survey said `status: ok` and exited 0; the one word of it was an event, which `--json` passed to no one, and the archive stayed incomplete for a later query to find. The survey document now says `status: incomplete` with an `archive_unfinished` warning naming the error, and the survey exits 9 (`store`, the shared contract's kind for a record that could not be written; owner ruling 2026-10-22) whatever its tables did, naming any failed tables in `details.failed`.
- **A `cli` command runs only where its mission says.** A `local` source whose directory did not exist ran the command in recon's working directory instead, so an `rg` or `git log` with a mistyped path mined whatever tree recon was started in, while the dry run showed the missing directory as its `cwd` and the survey said ok. A `local` source a run uses must now name a directory, or the plan has an `invalid_value` problem at its `url`, and the `cli` collector refuses to run anywhere else. The dry run's text names the directory each command runs in (`(in the working directory)` for none). A `cli` command runs in a source's directory only when the source is `local`.
- **The `rss-monitor` and `package-registries` templates fill every column they name.** `rss-monitor` read `link.@href` and `author.name`, which resolve to nothing because an Atom entry's links and authors are always lists, so every record's `link` and `author` were null; they are `link.0.@href` and `author.0.name`, and `cpython-releases` no longer asks for `published`, which GitHub's releases feed does not have. `package-registries`' PyPI collector read `info.home_page` and `info.license`, empty for a package on current metadata such as its own pydantic; it reads `info.project_urls.Source` and `info.license_expression`.
- **An empty table no longer reads as a source that had nothing** when recon could see otherwise. Three cases wrote `ok, 0 records` without a word: an `extract:` that resolves to nothing in a response that is not empty (a 200 carrying an error object, a changed shape), an extract whose items are not objects (a list of ids), and a `capture` collector whose filters kept none of the captures it read (an unpinned one over a catalog keeps only captures whose `source` is the catalog source's name, and MCP captures carry the server's). Each keeps its table, empty, with a warning: `extract_unresolved` (naming the keys the response has), `records_not_objects` or `captures_unmatched`. An empty list at the path is still a source that had nothing. A collector type signals this by raising `NoRecordsError` (`recon.domain.errors`) before its first record; `to_records` raises it for the built-ins. The skill's "a collector with `extract:` is never warned" now says it is not warned about the lists inside its records.
- **A query's rows keep every column.** A row is an object keyed by column, so `SELECT a.x, b.x` printed `columns: ["x", "x"]` and rows holding one `x`, the second value over the first, and the human table rows a cell short. A name the SQL gives twice is now made unique in `columns` and every row, with the suffix DuckDB gives it in a subquery: `x`, `x_1`, then `x_1_1` on a further clash.
- **A built-in transform given the wrong type nulls that field, not the table.** `$inverted_index` on a list, `$html2text` on an object, `$join` or `$first` on a number raised, and one such record failed the whole table as `unknown`. Each now gives `null` for that record's field, as a path that does not resolve does. `$join` and `$first` on a string gave its characters joined or its first character; they give `null` too.
- **A table's unclassified error has the kind `run_failed`**, as 0.11.0's notes and the README said; it was `unknown`, whose next step is "report it as a bug in recon". The survey's kind was already `run_failed`. Three HTTP client failures that are not transport errors are classified rather than escaping with no fix: a redirect loop (`TooManyRedirects`) and a body that does not decode as its Content-Encoding says (`DecodingError`) are `run_failed`, each with its own fix, and a source `url` and `endpoint` that do not make a URL (`InvalidURL`) is `config`. Each such request's span has `error.type` `httpx2.<class>`.
- **Placeholders are checked where recon fills them, and a regex's counts are not placeholders.** A `web` collector fills no placeholder, yet `endpoint: /page/{slug}` planned valid and was fetched literally; it is now a plan problem (`unresolved`). A placeholder's name begins with a letter or `_`, so `\w{3}` or `{2,5}` in an `api` `params:` value, which was refused as `unresolved` placeholder `{3}`, is sent as written. In a `cli` `run:`, recon fills `{url}` and `{pattern}`; `{url}` in a run with no source, which planned valid and ran literally, is now a plan problem, and fails the table before anything runs. A collector type may check each run against its source in the plan (`CollectorType.check_run`). Other braces in `run:` belong to the command (cargo's `--format '{p}'`, jq) and are passed as written: the skill said every unfilled placeholder was a plan problem, and now says which are.
- **An empty table's view keeps the columns its collector's `normalize:` names.** Its view had only `_empty`, so a query that runs on a full archive (`SELECT title FROM papers`) failed with a Binder Error, exit 10, on one whose source returned nothing. The empty sentinel line now keeps the spec's columns (`{"_empty": true, "_columns": [...]}`), and the view has them, with no rows, beside `_empty`. A collector without `normalize:` has no known columns, and its empty table's view is as it was.
- **Only a directory named as a survey names its archive is an archive.** Any directory under `archive/` counted, so a stray `notes/` sorted after the timestamps, became the latest archive, and every query failed with "no tables". A `meta.yaml` from a newer recon is read for the fields this one knows: a table error with a field it does not know made `status` fail as a defect (exit 1).

## 0.11.0

### Changed (breaking)

- **recon follows the exit codes and error envelope the capability CLIs agree on.** `conflict` exits 7 and `query` 10, each code one kind. A failed table's unclassified error has the shared kind `run_failed`, as its survey does; `collection` is gone. The envelope is `{kind, message, fix, complete, problems, details}`, and a problem `{path, kind, message, fix, allowed, got, source}`. A problem's `path` is dotted (`collectors.0.type`, was `collectors[0].type`), and its kinds are the shared ones: `missing_key`, `invalid_value`, `name_unknown`, `name_taken`, `wrong_shape`, `yaml_syntax` (were `missing`, `invalid`, `unknown_name`, `duplicate`). `recon.EXIT_NEXT` says what to do on each kind; `recon.ConfigError` is a `ValueError` and `recon.NotFoundError` a `KeyError`.
- **Warnings are problem records**, in the `warnings` list of `recon.v1.plan`, `recon.v1.survey` and now `recon.v1.query-rows`, with kinds `env_unset`, `plugin_broken`, `otel_unavailable` and `telemetry_failed`. They were strings.
- **`recon init` takes `-c/--config FILE`**, as `survey` does; `--from` is gone. `init` and the library's `recon.init` take `config=`, not `source=`.
- **A `local` source's relative `url` is relative to the project root**, not to the directory recon runs in, so a mission scans the same directories wherever it is run from.
- **A survey whose failed tables are neither credential failures nor all transient exits 8** (`run_failed`), not 1, which it shared with `unknown`.
- **`recon query --archive <id>`** names the archive to read; the flag was `--run`.
- **A `cli` command that exits 1 with something on stderr fails its table.** Exit 1 counts as success only when stderr is empty (grep's and rg's "no match"). A failed command's error ends with the last 4 KB of its stderr.
- **`$markitdown` fails the table on a file it cannot read or convert**, naming the file. It returned an empty string, which read as an empty document. A converter whose dependency is missing is a `config` error.
- **The operations return typed records** (`recon.SurveyDocument`, `recon.StatusDocument`, ...), one per `recon.v1.*` shape; `.document()` is what `--json` prints. A table's `error` in `meta.yaml` and the survey document always carries `fix`, null when there is none.

### Added

- **Telemetry.** Every survey writes its event log, `telemetry.jsonl`, into its archive: a `recon.v1.event` line at the start and end of each span (`recon.survey`, one `recon.collect` per table, one `recon.http.request` per attempt to send a request, with OpenTelemetry's HTTP client attributes, semconv v1.44.0). The same spans, and the counters `recon.collect.records` and `recon.collect.failures`, go through the OpenTelemetry API; with the new `otel` extra, setting the standard `OTEL_*` variables is enough for the `recon` command to export them over OTLP. `import recon` uses the API only and never installs the SDK; a program configures OpenTelemetry itself or calls the new `recon.configure_telemetry()`. No secret and no body is recorded.
- **`init` is idempotent**: run again with the same config, it changes nothing and succeeds. A different config is a `conflict` that names `--replace`, which `init` now takes. `recon.v1.mission` says what happened as `outcome`: `created`, `unchanged` or `replaced`.
- **`recon status <mission>`** lists every archive of that mission, oldest first, as the `history` of its one entry in `missions` (`missions[0].history`): each archive's `id` (what `query --archive` takes), `path`, `started_at`, `finished_at`, `state` and tables. Every `ArchiveStatus` carries the two times; the library's `recon.status()` takes the mission.
- **Query output says where its rows came from**: `recon.v1.query-rows` has `archive_id` beside `archive`, and the human output names the archive on stderr. `query --help` says where archive ids come from and how to read an older archive's table or a table's raw lines; a row is cited by its line in one archive's table file, which `WITH ORDINALITY` numbers (see the skill's Reading results; a glob across archives numbers all its files' lines as one, and their columns can differ).
- **Three warnings**, problem records in the document's `warnings`: `fan_out_mixed` when a plan's collector with no `source:` would run against catalog sources of different types; `extract_missing` when a survey's table of an `api` or `capture` collector with neither `extract:` nor `normalize:` gets one record holding a list of two or more objects, naming the path to set as `extract:` (a collector with `extract:` is never warned: its one record is a record, and a list inside it is its own); `table_unreadable` when a survey writes, or a query's archive holds, a table SQL cannot read. For collector-type authors, `CollectorType(extracts=True)` opts a type into the `extract_missing` check. Human output prints each warning's `fix`.
- **`-` reads a config from stdin**: `recon init m -c -`, `recon survey m -c -`.
- **The library takes `root=`** on `init`, `plan`, `survey`, `status`, `query` and `capture`: the project whose `.recon/` to use, so a program need not change directory.
- **`complete` says when checking stopped early**: false in the error envelope when part of the config could not be checked (an entry of the wrong shape, a file that is not YAML), so more problems may follow the fixes.

### Fixed

- **One table SQL cannot read no longer fails every query.** An OpenAlex record kept with its word-keyed `abstract_inverted_index` (surveyed without `normalize:`, as the probe step says) held keys differing only in case, DuckDB could not make a view of that table, and every query on every table failed as `unknown`, "report this as a bug". Each table's view is now made on its own: a query of the other tables runs with a `table_unreadable` warning naming the table, why, and the fix (normalize the field with `$inverted_index`, or read the raw lines with `read_ndjson_objects`); a query of that table fails as `query` (exit 10) with the same fix. The survey that wrote the table warns too, so it is found before the first query.
- **A failed query's fix is about what failed.** Every SQL error's fix was "query one of these tables", so `Binder Error: UNNEST not supported here` sent an agent looking for another table. Only a missing table is told the tables there are; any other error's fix quotes DuckDB's message and links DuckDB's SQL documentation, `unnest` beside an aggregate is given the subquery that works, and a binder error from a glob that spans archives (`archive/*/<table>.jsonl`) says their columns can differ and to read one archive's file by its path. `EXIT_NEXT` for `query` says so.
- **The dry run shows the request a run would send.** An `api` run showed its URL without the query string, so `params:` (search, filter, per_page) and an `auth.param` were invisible; it now shows the method, the URL with every query parameter, the headers the mission decides (User-Agent, the auth header) and the body, with the credential `REDACTED` as telemetry has it. A `web` run shows its method and headers too.
- **An unknown key no longer hides the other problems of its entry.** A collector with a misspelt key and an unknown type reported only the key; the entry is now checked again without the key. A collector naming a source that did not parse is no longer also told the source is missing.
- **A URL's own query string is kept.** A web source or endpoint with `?id=3` was fetched without it; params are now added to the query rather than replacing it.
- **Human output is not wrapped off a terminal**, so a piped path or command stays whole; tables are laid out as wide as their cells.
- **Ctrl-C under `--json` prints the envelope as stderr's first line**; a blank line came before it.
- **`recon capture` on a terminal says what it wants** (exit 2, usage) instead of waiting in silence for a payload.
- **`init -t` with `-c` is a usage error**; the template was ignored without a word.
- **An archive reads incomplete unless its survey finished.** The marker is written when the archive is made and removed only after `meta.yaml` is written with every table succeeded, so a survey stopped by SIGTERM or killed no longer reads `ok`.
- **SIGTERM is handled as Ctrl-C:** the survey exits 130 and kills the command its current table was running, which kept running before.
- **A `cli` command's timeout holds while it is still printing**; it applied only once stdout closed, so a command that never closed it hung the survey.
- **A command that writes a lot to stderr no longer blocks** on a full pipe; stderr is drained as the command runs.
- **A `cli` command's stdin is empty.** It inherited recon's, so a tool that reads stdin when given no path could wait on it until its timeout.
- **Every collection error carries a `fix`**: HTTP failures by kind, a timed-out or failed command, a body that is not the declared format, a capture line that cannot be trusted.
- **The built-in templates send the default User-Agent**, which names the running version; they had set `recon/0.9.0` explicitly. The `package-registries` template's usage named a template that does not exist.

### Packaging

- recon is installed from the repository at its release tag: `uv tool install "git+https://github.com/mox-labs/gnx@recon-v0.11.0#subdirectory=components/capabilities/recon"`. The package carries a readme, its license file, classifiers and project URLs.

## 0.10.0 — 2026-10-12

Fixes for cases where recon gave a wrong answer without saying so, and for three places where collected data or an installed plugin could reach further than the mission's config allowed.

### Changed (breaking)

- **An empty table reports `records: 0`.** It reported 1, because the `{"_empty": true}` line that keeps the file readable was counted, and `SELECT count(*)` on the table returned 1. The line is still written; it is no longer counted and the table's view has no rows. `meta.yaml` files written by 0.9.0 keep the number they recorded.
- **An unresolved `{placeholder}` in a `params:` value is a config error** at plan time, located as `collectors[i].params.<key>`. The parameter used to be left out of the request without a word. So was any value that merely contained a `{` (a SPARQL query, a JSON filter); those are now sent as written.
- **`recon query` is confined to the mission's archives.** SQL can read files under `.recon/<mission>/archive/` (earlier archives included) and nothing else: no other path, no `INSTALL` or `LOAD`, no URL. It used to run on an unrestricted DuckDB connection, where `read_text('/etc/hosts')` returned the file.
- **`$markitdown` reads only what the mission declares and never fetches.** The file a record names must be under the mission directory or a catalog source with `type: local`; a URL (`http:`, `https:`, `file:`, `data:`) is refused. Either is a config error with a fix, where it used to fetch the URL or read the file. Use a `web` collector to fetch a document.
- **A response body is bounded.** A source has `max_bytes` (default 50,000,000, counted after decompression). A larger body fails its table with kind `collection` instead of being buffered. Raise `max_bytes` on a source that serves larger documents.
- **The default User-Agent is `recon/<version> (+https://github.com/mox-labs/gnx)`** for `api` and `web` sources. An `api` source with no `user_agent:` used to send a desktop browser's string. A source's own `user_agent:` is sent as written; set one for a site that refuses the default.
- **For collector-type authors:** recon applies `normalize:` to the records of any type that does not declare `normalizes=True`, so a type that applies the spec itself must now say so. `ctx.env` holds only the `auth.env` variables of the sources that type's collectors use; reading any other name raises a config error. `ctx.user_agent` is what to send when a source sets none. A `Problem` carries a `kind`, a `fix` and the value written (`got`).
- **Every failure prints one envelope**, `{"schema": "recon.v1.error", "error": {"kind", "message", "fix", "details", "problems"}}`: a usage error and Ctrl-C included, which used to print click's prose or a traceback. Values that sat beside `kind` (a failed survey's `archive` and `failed` tables) are in `details`. A problem carries `path`, `kind`, `message`, `fix` and `got`. For a person, the first line reads `error (<kind>): <message>`.
- **Ctrl-C exits 130** with kind `interrupted`, the code every gnx capability CLI uses; the exit codes are `recon.EXIT_CODES`, held to `components/capabilities/exit-codes.json`.
- **`-r` names a reference that exists.** `recon --skill -r <unknown>` exits 2 and lists the names; `-r` without `--skill` is a usage error. Each reference prints with `-r`, including `capture-format`; the docs page `docs/reference/capture-format.md` is the same text, and a test holds the two equal.
- **`response_format: html` or `text` on an `api` collector is a plan problem.** It wrote a table with no records and reported success. A `capture` collector still takes both.
- **`init` has no `research` template redirect**; an unknown template is `not_found` with the list.
- The skill's `examples/` directory is gone: its missions are in `-r config-patterns` and in the skill text, and every mission the text shows is planned by the tests.

### Added

- **A library API.** `import recon` gives `init`, `plan`, `survey`, `status`, `query`, `templates` and `capture`, each returning the document the CLI prints under `--json`, plus `survey_failure`, `skill`, the errors and the tables `EXIT_CODES`, `EXIT_MEANINGS`, `ERROR_KINDS` and `PROBLEM_KINDS`. The CLI calls only these.
- **`query --json` says `state: incomplete`** for an archive a table failed in, whose rows may be partial; only the human output warned before.
- **A survey cut short by Ctrl-C marks its archive incomplete**, so `status` and `query` no longer take it for a whole one.
- **Determinism is a tested contract**: the same mission and the same answers from its sources give the same records, and the time reaches an archive only through the clock port (`recon.application.survey`).
- Top-level config keys beginning with `_` are ignored. A config can hold notes, or a YAML anchor that several collectors alias (`_normalize: &spec {...}`), without tripping the unknown-key check that 0.9.0 introduced. Every other unknown key is still an error, and so is a `_key` inside a source or collector.
- `max_bytes` on a catalog source.
- A failed table's `error` carries a `fix` when the error names its remedy, in `survey --json` and `meta.yaml`; an error that escapes a command keeps its own `fix` on the `--json` error line.

### Fixed

- `recon --help` lists every exit code with what to do next.
- The CLI runs on rich-click, like the other capability CLIs. Paths are resolved by recon's own code instead of glom, with the same results for every path the normalize reference documents; a list index (`authors.0.name`) and a bare `*` over an object's values are documented.
- A plugin collector type that did not apply `normalize:` wrote raw records for a config the plan had accepted. The spec is now applied for it.
- A collector type's factory was handed the whole process environment.
- The built-in `factual-ground` template's SPARQL `query` parameter was never sent (it contains braces).

## 0.9.0 — 2026-10-09

Agents are recon's main callers, so this release makes its boundary say what happened in a form a program can act on, and plans every survey before it touches anything.

### Changed (breaking)

- **Mission directories now live in `.recon/`** (`.recon/<name>/` at the git root, or the current directory outside a repository). The previous location is not read. To keep an existing mission, move its directory under `.recon/`.
- **A survey in which any table failed exits non-zero.** It used to exit 0 and leave only an `.incomplete` file. The archive is still written and every table's status is still reported; the exit code is 6 if any table failed on credentials, 5 if every failure was transient, 1 otherwise.
- **Errors exit with classified codes** shared with hardline and ix: 1 unclassified, 2 usage, 3 config (including a `conflict` and bad SQL), 4 not found, 5 transient, 6 auth. Errors that used to exit 1 now exit 3 or 4 where they are config or not-found.
- **`query --json` prints a document**, `{"schema": "recon.v1.query-rows", "columns", "rows", "count", ...}`, instead of a bare list.
- **An unknown transform is a config error.** `x|$typo` used to be skipped silently and leave the value untransformed.
- **Config keys are checked.** An unknown key (`normalise:`, `preserve-raw:`) is a config error with its path, instead of being ignored.
- **`survey -c FILE` no longer overwrites a mission's existing, different config.** It exits 3 (`conflict`) and suggests `--replace`.
- **`preserve_raw` writes a capture log** — `archive/<ts>/captures.jsonl` with bodies under `raw/<sha256>` — instead of `raw/<collector>/body` + `meta.yaml`.
- **`meta.yaml` is `format_version: 2`**: a `tables` list (was `collectors`) with each table's `type_url`, and `error: {kind, message}` (was a string), plus `recon_version` and `config_sha256`. `status` and `query` still read format-1 archives.
- **The `Collector` port** takes `captures: CaptureLog | None` instead of `raw_store: Any`, and `ApiCollector`, `CliCollector`, `WebCollector` take an optional transforms mapping. Transforms are registered by name without the `$`.
- The `$pdf2text` transform the docs described never existed; `$markitdown` (any document markitdown reads) is the one that does.

### Added

- `survey --dry-run` / `-n`: validates the config, resolves every collector × source run with its declared effects (network, subprocess, filesystem) and the URL or command it would use, and lists every problem with a path such as `collectors[2].normalize.title`. No network call, no subprocess, nothing written. Every survey runs the same plan first, so an invalid config never creates an archive. Unresolved `{placeholders}` in an API endpoint or body are caught here.
- `--json` on `survey`, `status`, `templates`, `init` and `capture`. Every document carries a dotted `schema` (`recon.v1.survey`, `recon.v1.plan`, `recon.v1.status`, ...). With `--json`, an error is one `{"error": {"kind", "message", "fix", ...}}` line on stderr.
- Collector types and transforms are extensions: entry-point groups `recon.collectors` and `recon.transforms`, with the built-ins registered the same way. A plugin that fails to load is reported by `status` and `--dry-run` and does not affect the others. See docs/reference/extending.md.
- A `capture` collector type that normalizes capture logs (a path or glob, filtered by source / collector / kind), and `recon capture <mission>`, which appends a Claude Code `PostToolUse` hook payload to the mission's capture log. The capture format is specified in docs/reference/capture-format.md; the hook setup in docs/how-to/capture-mcp-results.md. New template: `mcp-captures`.
- `type_url:` on a collector (dotted grammar; default `recon.v1.records`), recorded per table in `meta.yaml`.
- `auth.param` sends the credential as a query parameter (it was declared and ignored). Its value is redacted from captured URLs.
- `status` lists the installed collector types and transforms, and each mission's external capture count.

### Fixed

- HTTP failures carry a kind: 401/403 are `auth`, 429/5xx/transport errors `transient`, so a survey's exit code says whether to retry or re-key.
- Templates and docs pointed at the old repository; they now point at the gnx repository.
